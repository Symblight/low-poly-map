# Addon notes (`addons/simworld/`)

Implementation notes of the Godot addon, moved out of `CLAUDE.md` on 2026-10-30. The contract (`docs/contract.md`) wins on any detail; the user-facing install / use guide is `addons/simworld/README.md`.


- `runtime/` (namespace `SimWorld`, compiled into the host's assembly; `WorldView`, `TilePool` and the facade are partial classes split by concern: `WorldView.Frame/Upload/Fades/Unload/Time/CullMargins/Debug/Timings/Taps/View.cs`, `TilePool.Fades/Sprites/Warmup.cs`, `WorldStreamerFacade.Ready/Lod.cs`): `WorldView` (the entry node: owns the streamer, runs the per-frame calls, uploads, fades, shifts the origin; no default origin, no command line; `AutoStart` or `Start()`, `SetTime(hour, night)`, C# event `OriginShifted`), `IWorldCameraSource` (+ `Camera3DSource` adapter; a `Camera3D` needs no code; `CameraSwitchSource(Func<Camera3D?>, all, velocity)` for a host that switches cameras (pass the vehicle's velocity: a chase camera's swing fed into the 20 s look-ahead moves the whole cover), with `IWorldCameraTick` / `IWorldCameraProvider` and `WorldView.ViewCamera` = the source's camera or the `Camera` export), `WorldRenderSettings` (resource: upload budget, prewarm, debug, building/ground/light-sprite material tunables), `NightLook` (resource: glow threshold/intensity and fog on an `Environment` the host passes in; `ApplyFog` false = glow only, for a host with its own fog writer; exposure, tone map, sun, sky stay in the host), `ShaderGlobals` / `AddonPaths`, `SimWorldPlugin` (editor plugin), `WorldStreamerFacade`, `TilePool` (+ `SpriteCells` / `SpriteCell`: the point sprites of the R2 / R3 tiles merged into one mesh per spatial cell, see `docs/bench/notes.md` "Light sprites"), `TileCover`, `TileKey`.
- Terrain (api 1.5, host side built): `WorldView.EnableTerrain` (opt-in, sends `layers: ["world","terrain"]`) plus `terrain_center` = the startup origin (api 1.6, so a reconfigure that moves the origin keeps the relief) and reads `status().TerrainActive` and `TerrainEnabled` (profile override `terrain.enabled`), `TerrainCover` + `TerrainPool` / `TerrainNodes`, `shaders/terrain.gdshader`, `WorldRenderSettings.Terrain*`, `SetTerrainDetail`, `TileKey.TryParse(key, out packed, out isTerrain)`; the camera far plane (reach x 1.15) and the day fog are host policy (`NightLook.TerrainDayFog*`). Default off = the flat world exactly.
- Frame cost (host performance pass; no contract change): releasing a tile (`TilePool.Release` / `TerrainPool.Release`) hides the set at once and queues it (`RetireQueue`), `DrainRetired` clears its meshes and sprite sets within `WorldRenderSettings.ReleaseBudgetUs` (1 ms, at least one set per frame per pool), `Acquire` clears a retired set on demand and never hands one out before it was cleared; `FreeCount` = free + retiring. The point sprites (one points mesh per tile, plus the street pools) sit under one `TileNodes.Sprites` container that `WorldView.SetTime` hides while the night factor is below 0.02 (shown again above 0.05; `TilePool.SetSpritesVisible`, one call per held tile on a change, new sets follow the pool's state): by day they drew only additive black. Beacons go with them (their shader is also zero by day); a daylight strobe would need a day term in `light_sprite.gdshader` (kind beacon) and its own container. Sprite uploads stage through shared per-size arrays (`PointPacker`, padded to 256 / 1024 vertices, no per-tile buffers; the pool MultiMesh capacity only grows, `PoolWriter`). `MaterialPrewarm` draws the 10 world materials, the dither variants included, tiny in front of the camera for 24 frames at start (`PrewarmMaterials`; skipped headless) so the shader / pipeline compile does not hit the first fade, and in the same frames makes the dither clones a fade burst needs (`fades.max_active` x `WorldRenderSettings.FadeReserveTilesPerSwap` tiles x 4 nodes, plus the terrain's). Frustum-cull margins are per tile (`CullMargins`, `WorldView.CullMargins.cs`): the earth-curvature drop at the tile's far edge plus 600 m of slack, floor 0.5 m, written at upload and re-checked 4 times a second (`WorldView.CullMarginWrites`); `TilePool.CurveCullMargin` stays only for the runway markings. `poll_fades` is read without allocating while its key set is unchanged (`FadeKey` cache in `WorldView.Fades.cs`; the dictionary is enumerated and the key strings parsed only when a fade starts or ends). Debug checks (`WorldRenderSettings.DebugChecks`, default off; the bench turns them on for headless runs, `*-selftest`, `--geodetic-test`, `--hole-check` and `--debug-checks`, never for `--benchmark` / `--soak`): the periodic `VerifyCover` and the first-tile `debug_stats` print. Delivered tiles the host cannot draw (an entry without a key, a mesh array that is not an Array or has no vertex slot, a mesh Godot rejects, a short light colour array, a non-Array `poll_ready`) are logged once per key and counted (`WorldView.UploadProblems`, F1 overlay "UPLOAD PROBLEMS"). `AsMeshArrays` no longer copies the vertex array to read its length (the arrays go straight into `AddSurfaceFromArrays`).
- Managed allocation and GC (host performance pass 4; no contract change; ranked sources and the pause analysis are in `docs/bench/diagnostics.md`): the .NET collector's pauses (5 to 10 ms a gen0, 10 to 30 ms a gen2, the main cause of 20 to 40 ms frames) are proportional to the handles Godot's C# layer creates, not to the bytes, so the frame loop disposes every `Variant` / `Godot.Collections` wrapper it takes, reuses argument arrays and keeps `StringName`s static. `WorldStreamerFacade` was split (it was 1058 lines): `.Frame.cs` (update_camera, geodetic calls, ground height, poll_fades / poll_unload / take_origin_shift), `.Stats.cs` (debug_stats, debug_tiles), `.Seed.cs`, `StreamerRecords.cs` (the result records); `PollReady(int, List<ReadyTile>)` replaces the raw-dictionary call and `ReadyTile.ReleaseHandles()` frees a tile's mesh handles after its upload; `PollFades()` returns null when no fade runs; `MeshSurfaces` is an instance per pool; `AllocProbe` (addon) books the main thread's allocation to the frame loop's sites for the bench report; `GcPacer` / `WorldRenderSettings.GcQuietBudgetMb` (default 0 = off, benchmarks included; `--gc-quiet=64` to try it) keeps the collector out of the frame loop with a no-GC region: game policy, never turned on by the addon; one pacer per process (`GcPacer.Acquire` / `Release` count the views, `Tick` runs once per process frame), a rotation is end region + start the next (the start runs the one full blocking collection, no extra `Collect(0)`), a refused start backs off 10 s, `NOTIFICATION_OS_MEMORY_WARNING` ends the region, collects and holds 60 s, `RotateNow()` for a quiet moment the game knows, and the last view's `_ExitTree` ends the region with a collection plus `WaitForPendingFinalizers` (ending it without one left a budget of finalizable wrappers to Godot's teardown: finalizer thread into a destroyed engine mutex, abort); `PointSurface` is an instance per owner that disposes its byte Variants like `MeshSurfaces`. **Soak verdict (2026-10-29, `docs/bench/diagnostics.md` "GC pacing"): at 64 MB and at 16 MB the pacer is a net loss (worst rotation 184 ms / 224 ms, a managed heap that grows across rotations because a whole region's finalizable wrappers survive to be finalized, frame p50 doubled by the end of 600 s), so the game should leave it at 0; the finalizable-object rate is the thing to cut.** What still allocates per frame and cannot be fixed in the host: the Array, Dictionary and PackedStringArray the library returns from `poll_ready` / `poll_fades` / `poll_unload` on every call (540 B, 3 finalizable objects), and the four light arrays per tile copied into managed arrays (140 to 190 KB/s, some above the 85 KB large-object limit).
- Screen-space LOD (api 1.10, host side built, gated: a library below 1.10 gets nothing and logs one `set_view unavailable` line): `WorldView.UpdateView` sends `set_view(fov_y_deg, viewport_h_px, forward)` before `update_camera` on change (fov > 0.05 deg, height, direction > 2 deg) and after every configure, `WorldRenderSettings.LodPixelScale`, `SetViewOverride` (bench `--view=` / `--cam-fov=`), facade `HasSetView` / `SetView` / `SetViewCalls`, `StreamerStats.TauEff` / `LodQuality` / `LodEdgesM` / `ViewFovYDeg` / `ViewHeightPx` / `DataTiles*` / `RequestsSkipped*`. S2 + S3 host half: `LatestKnownMinor` = 10, facade `SetLodQuality` (gated 1.10), `WorldView.SetLodQuality` / `ReadLod` / `LodEdgesM` / `TauEff` / `LodQuality` (the band edges are no longer fixed: `BandsText` shows the live `lod_edges_m`; `bands.rN_edge_m` in `profile_overrides` is a profile error), `WorldRenderSettings.BlendFollowsLod` (the window / sprite blend, the street pool fade and the sprites' far fade follow `lod_edges_m`, see low-poly-map/CLAUDE.md), the runway marking ring edges follow the live edges, settings panel = live Detail slider + Max distance, bench `--area` = `set_lod_quality(1/area)` + `bands.max_distance_m`, headless / self-test runs pin the view to 60 deg / 1080 px, `--lod-selftest`.
- Landmark layer (api 1.11, host side built, gated: a library below 1.11 is never sent `"landmarks"`; contract 9b): `WorldView.LandmarksEnabled` (default true; bench `--no-landmarks`) adds `"landmarks"` to `layers` on every configure and reconfigure (with `"terrain"` when that runs), `LandmarksActive`, `TileKey.TryParse(key, out packed, out TileLayer layer)` (`TileLayer` = World / Terrain / Landmarks; the 2-argument overload still means a plain vector key), `LandmarkCover` (`WorldView.LandmarkCover`: a flat `Dictionary` of `l/z/x/y` tiles, visible from upload to unload, no quadtree rule, no dither, shifted with the origin, cleared by the reconfigure's unload batch plus a stray sweep) over nodes from the SAME vector `TilePool` (building material with the windows, light sprites that cross-fade with the windows like R1, beacons; no ground / street / airport sets), `ReadyTile.IsLandmark`, `DebugTile.Layer` / `TileState.Empty`, `StreamerStats` `HasDataLevels` / `DetailZoom` / `OverviewZoom` / `TwoLevel` / `LandmarksInArchive` / `LandmarksLoaded` / `Pending` / `Empty`, counters `LandmarkReadyTotal` / `LandmarkKeysSeen` / `LandmarkFadeKeysSeen` (must stay 0). `LatestKnownMinor` = 11. The pool in use equals vector + landmark tiles. Terrain: `set_terrain_detail` is a tau scale since api 1.10 (`WorldView.TerrainTauPx` / `TerrainTauEff`), the settings slider is the raw scale labelled coarseness.
- Render height, pool trim, memory budget (host only, no contract change): `set_view` carries the **3D render height** = the camera viewport's height x its `Scaling3DScale` (project setting `rendering/scaling_3d/scale`) x `WorldRenderSettings.LodPixelScale` (an extra bias, default 1); `CameraViewReader` measures it every frame, so a window resize or a scale change re-sends `set_view` (the light sprite pixel scale uses the render height too); `WorldView.ViewHeightPx` / `ViewportHeightPx` / `RenderScale`, one `[WorldView] set_view ... render height` log line per change, F1 `view:` line and `LatencyLog` show it; a `SetViewOverride` height is used as is. `PoolTrimmer` gives idle pool memory back: `TilePool` (vector + landmark nodes) and `TerrainPool` destroy free node sets (`Trim(delta)` once per frame from `WorldView`, a few per frame within 0.5 ms) when the free list stayed above `max(PoolTrimMinFree 64, PoolTrimPeakShare 0.25 x recent peak in use)` for a whole `PoolTrimHoldS` (30 s, tumbling window, 0 = never shrink) window; `TotalCreated` / `PoolCreated` is the number of sets that EXIST now (so tile roots == created still holds), `Trimmed` the destroyed ones; `[PoolTrim]` log lines. `WorldRenderSettings.MemoryBudgetMb` (`MemoryBudget.Apply`): passed as profile override `memory.budget_mb` on every configure unless the host's overrides or profile file carry the key and the library has api 1.10; 0 = library default (512), the property default is 224 on mobile (`OS.HasFeature` mobile / ios / android) and 0 on desktop. Bench: `--render-scale=`, `--memory-budget-mb=`, `--pool-trim-hold=`.
- Engine surfaces (api 1.11, host side built; contract 3.1 / 4 / 4a): `WorldRenderSettings.EngineSurfaces` (default on) makes `WorldView` pass `engine_surfaces = true` to `configure_world` when the facade says api >= 1.11 (`HasEngineSurfaces`, `AddEngineSurfaces`; `WorldView.EngineSurfacesActive`, `WorldView.Options.cs`); the ready tile then carries `MeshSurface` / `GroundSurface` / `TerrainSurface` (`ReadyTile`) and `MeshSurfaces.Fill` hands the bytes to the pooled `ArrayMesh` with one `Set("_surfaces", [surface])` (never `RenderingServer.MeshAddSurface` on an ArrayMesh: stale surface list and AABB); the Arrays path stays for an older library or the switch off (bench `--no-engine-surfaces`). Materials are `MaterialOverride`s, so nothing else changes. Street sprites (api 1.11 `spacing_scale`): `light_sprite.gdshader` reads a street point's lamp count as `(8 a)^2` and draws it that many times as bright below the light-carpet altitude (`street_cluster_agl_m`, 2700..3300 m, mirrors `lights.cluster_off_agl_m` / `cluster_on_agl_m`), keeping the cluster model above it.
- World seed S1 (api 1.7, host side built; `docs/spec-world-seed.md` 11d): `WorldView.SeedWorld` (path of a `world.json`; non-empty = seed world: `TileUrl` ignored with a warning, terrain layer forced on, profile overrides `terrain.enabled` true and `flat_radius_m` / `flat_blend_m` 0 added unless the host set them, `cache_dir` empty, `seed_world` passed on every configure and reconfigure), `SeedWorldActive`, `SeedInfo` (`seed_world_info()` as a typed `SeedWorldInfo` record, logged at start), `Airports` (`airports()` as `AirportInfo` / `RunwayInfo` / `RunwayEnd` records, re-read on configure and on every origin shift), facade wrappers `Airports()` / `SeedInfo()`, `ReadyTile.AirportLights`, `DebugTile.Source`. Shaders: `ground.gdshader` class 7 aeroway by sub-kind (COLOR b) and the countryside tint (COLOR g on class 0 / 1 areas; roads are told apart by r == 8/16 first), `terrain.gdshader` class colours from the seed terrain COLOR (r = class / 8 as one-hot weights; r * 8 == 8, i.e. a missing COLOR, keeps the altitude palette), both through `seed_palette.gdshaderinc` (`WorldRenderSettings.Seed*`). Airport lights (`airport_lights` / `airport_light_colors`): the third kind of the tile's points mesh (`SpriteKind.Airport`, `WorldRenderSettings.AirportLight*`: fixed colours, no window cross-fade, no grazing / altitude thinning, brightness scaled by alpha / 0.35 through the vertex's brightness byte, alpha 0.125 in COLOR so the sprite shader does not read them as clusters). Runway markings: `AirportMarkings` (edge lines, dashed centreline, threshold bars, aiming-point bars from the `airports()` runway ends, one mesh for the airports within 4.5 km of the camera, rebuilt on origin shifts) with `airport_marking.gdshader`; the drawn runway sits above `ground_height_at` by stacking level 3 x `ground.rN.lift_step_m` per ring (0.06 / 0.18 / 0.45 / 1.5 m; no drape lift inside an airport fence, generator 2, contract section 9 "Airports"): `WorldView.ComputeRunwayLifts` uses that rule when `seed_world_info()["generator_version"]` >= 2 (`WorldRenderSettings.MarkingRunwayLevel` = 3; `WorldView.RunwayLift` / `RunwayLiftRule` expose the result) and, for a generator-1 or older library, still replays the old drape rule (terrain bands x `detail_scale_max` + level 10 x step: 1.2 / 3.6 / 9.5 / 25 m). Bench: `--world=`, `--seed-spot=`, `--seed-selftest`, `SeedTwoCities.tscn`, F1 seed line.
- Dither fades (`FadeMaterials`): a fading tile rents one clone of the dither variant per drawn node (building, ground, point sprites, street pools; terrain 1) and writes `fade` / `fade_parity` / `fade_mul` as plain uniforms. **Never use `instance uniform` in an addon shader:** Godot gives every node that is assigned a material declaring one 16 entries of a 4096-node buffer for good and reads them as 0 once it is full (invisible tiles, black sprites; see CHANGELOG). Parameters of the world materials go through `TilePool` / `TerrainPool` setters, which write the template and every clone. `--fade-selftest` guards it.
- Shader globals `simworld_night_factor`, `simworld_hour`, `simworld_curve_center`, `simworld_curve_inv_2r`: the editor plugin writes them into `[shader_globals]` when enabled; `WorldView` adds any that are missing at runtime. `GlobalShaderParameterGetList` is editor-only: never use it at runtime.
- Asset paths come from the script's resource path (`AddonPaths.Root`); shader `#include`s are relative (the dither variant rewrites them to absolute because an in-memory shader has no path). `build_addon.sh` fills `bin/`; the release zip (P7) is this folder with `bin/`.
- `TerrainCollision` (optional, `WorldView.TerrainCollisionEnabled`, default off): one `StaticBody3D` + `HeightMapShape3D` patch (33 x 33 samples, 40 m apart) centred under the camera, filled from `ground_height_at` and re-centred/shifted with the camera and origin; the exact heightfield, not the drawn terrain triangles (differ by up to the band `max_error_m x detail`); no collision for buildings or far terrain.
- Not done: the minimal iOS export of a project that uses the addon (needs the iOS rust target, Xcode and Godot's iOS .NET export; the plan has a fallback if C# on iOS is blocked), `ios` `.gdextension` entries are written but unbuilt; Windows and Linux libraries are built only on those hosts (CI, P7); the profile colours / lit shares as shader globals wait for the window shader (M6).
