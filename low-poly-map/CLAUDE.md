# CLAUDE.md (test bench)

Test-bench notes only. Project status, layout, commands, architecture, constraints and the library plan are in the repo-root [`../CLAUDE.md`](../CLAUDE.md); the single contract document is [`../docs/contract.md`](../docs/contract.md) (read it before changing either side; do not copy it here) and the specs are in `../docs/`. This folder is the Godot 4.7 .NET project (renderer Mobile, Jolt) that hosts the `WorldStreamer` GDExtension from `../rust/` (workspace crate `simworld-godot`, library `libsimworld_godot.*`, wrapping `simworld-core`) and flies a camera over the streamed city.

## Run it

- `G=~/Downloads/Godot_mono.app/Contents/MacOS/Godot`; build Rust first (`cd ../rust && cargo build`), **sync the addon** (`../tools/sync_addon.sh`: `addons/simworld/` here is a generated, git-ignored copy of `../addons/simworld/`; edit the source there) and C# (`dotnet build`). The plugin `res://addons/simworld/plugin.cfg` is enabled in `project.godot`.
- Play: `$G --path .` (or F5 in the editor; main scene `scenes/CitySpike.tscn`). User arguments go after `--`, e.g. `$G --path . -- --time=13:00 --date=06-21`.
- Tile source: `http://127.0.0.1:8787/vilnius.pmtiles` by default (start `../data/serve.sh`; tiles already in the disk cache at `user://tile_cache` render offline). `--tile-url=` (empty) switches to the synthetic city.
- Headless smoke test: `$G --headless --path . --quit-after 120`. Expect `[WorldView] tile source`, `[WorldView] library api <major>.<minor>` (a `predates api_version` warning means a stale dylib; the facade expects major 1 (`ExpectedApiMajor`) and refuses every 0.x library with an error naming the fix, i.e. rebuild `../rust`; a library minor above the facade's `LatestKnownMinor` = 11 prints one `[WorldStreamerFacade] ... is newer than the facade's 1.11` info line, which is fine), `poll_fades available`, `WorldStreamer configured ... [simworld-godot <ver> (build ...)]`, the disk cache line, `attribution`, `effective edges` (tau_eff, quality, library view, live edges), `status: ok` and a `first tile` line, with no errors. On exit `[WorldView] shutdown` shows the cache lock was released. `slow upload` lines are informational.

## Keys and menus

- Fly: hold the right mouse button to look, WASD, Q/E down/up, Shift x4, Ctrl x10 (turbo), mouse wheel changes speed (default 80 m/s, no speed cap; altitude and speed in the overlay), F toggles the autopilot, PgUp/PgDn double/halve altitude, hold Z = 4x zoom (the vertical fov divides by 4; for the screen-space LOD tests).
- F2: daylight menu (bottom right). Time slider 0-24 h, date slider (day of year), clock speed (paused, 1x, 1 min/s, 10 min/s, 1 h/s), presets for the chosen date (Sunrise, Noon, Dusk, Night), a night-factor override, and a readout of sun elevation, azimuth, night factor, origin and UTC offset. Controls never take keyboard focus, so flying keeps working.
- F1: detailed debug overlay (FPS, draw calls, per-ring stats from `debug_stats`, upload time, tile rects, status / attribution lines; the terrain line shows the effective terrain tau = `terrain.tau_px` x scale, higher = coarser; a `jobs:` line (`jobs_queued` / `running` / `cancelled`), a `memory MB:` line (`memory_mb`: budget, total, data_tiles, height_tiles, over_budget, then any other pool) and the data tile counters (`data_tiles_*` keys shown generically, e.g. a future `evicted`; `requests_skipped_*` only if the library ever sends them: the contract does not define them), all hidden when the key is absent (`LatencyLog` prints the same); a `data levels:` line (two-level or compat archive, detail / overview zoom) and a `landmarks:` line (api 1.11: `landmarks_loaded` / `pending` / `empty`, landmark nodes held with their triangles, lights, beacons and upload ms; `[l/ KEYS IN poll_fades]` would flag a contract break). Off at startup: only the FPS label is on screen by default. H: outline hidden tiles, M: minimap zoom (both only while F1 is on).
- F3: settings panel (bottom-left, hidden at startup; `SettingsMenu`). Controls never take keyboard focus (only the speed number box while typing; Enter or a click outside releases it).
  - Movement: speed slider (log scale 1..2000 m/s) and number box (no cap), two-way with `FreeFlyCamera.Speed`, so the mouse wheel moves the slider. Live.
  - Level of detail (api 1.10; the four fixed band edges are gone): **Detail** = `set_lod_quality(1 / detail)`, log slider 0.25..4, RIGHT = MORE DETAIL (2 doubles every refine distance, 0.5 halves them; live, debounced 0.3 s, no restart, no teleport; the library keeps it across reconfigures); **Max distance** = `bands.max_distance_m` (50..100000 m, default 25000, the R3 edge; restart-type like the filters below); a read-only line shows the live tau, fov, H and the refine distances R0|R1|R2 | max from `lod_edges_m` (`WorldView.LodEdgesM`). Reset = max distance 25000 and detail 1. Terrain section: **Terrain detail** = `set_terrain_detail(1 / detail)`, same direction (range 1 / `detail_scale_max`..4; above 1 is expensive, see the tooltip) with a live line of the effective terrain tau; `SettingsMenu.LodQuality` / `TerrainDetailScale` stay the raw library scales (`Detail` / `TerrainDetailLevel` = 1 / scale). `--area=` and `--terrain-detail=` keep the raw library scale (no inversion).
  - Hide buildings lower than: `buildings.r0/r1/r2.min_height_m`, 0..100 m (profile 2; rows are disabled on a library without the keys).
  - Light sprites: "Lights from band" `R0..R3` = `lights.min_ring` (profile 3; default R1 since profile version 4, was R2): the finest band that gets light sprites. With R1 the windows of R1 buildings and their sprites cross-fade over 900..2000 m of view depth (night windows W4); R2 = sprites on R2/R3 only, R1 windows then fade to nothing with no sprites; R0 puts sprites on R0 too. Launch form: `--set=lights.min_ring=2`.
  - Max distance and heights are profile values read at configure time, so they apply by restarting the world: Apply button, or auto-apply 0.6 s after the last change (checkbox, default on). Each section has a Reset (library defaults; the initial slider values are the effective ones the bridge runs with, incl. `--area`/`--set`/`--profile`). The status line shows the effective values after every apply and tiles loaded / queued.
  - The panel's values are merged over the launch-arg profile (panel wins). A rejected profile keeps the previous world running, shows the library's error in red at the bottom and in the console, and reverts the sliders. The bottom line carries the attribution.
  - Origin on apply (`WorldView.ApplyProfileOverrides`, queued and run at the start of the next `_Process`, before `update_camera`): `configure_world` is a teleport (new origin, every delivered tile comes back through `poll_unload`), so the bridge configures with the camera's current geodetic position (`local_to_geodetic`, f32: up to about 0.4 m of jump) as the new origin, takes the unload batch immediately (before any new delivery can reuse a key; stragglers are released too and warned about), puts the camera at local x/z = 0 (altitude and orientation kept), clears its shift bookkeeping and fade list, and keeps the same `cache_dir` (lock kept, no `shutdown()`). Tiles are back within a few seconds. `WorldView.OriginLat/Lon` stay the startup position (the clock reads them).
- T: tone map Filmic/AgX. X: external view (auto exposure) on/off.
- F4: performance overlay (`Diagnostics/PerfOverlay`): off, FPS + frame ms, + frame-time graph (300 frames, red 33.3 ms / green 16.7 ms line), + the full table (see "Diagnostics"). `--perf-overlay=fps|graph|table` starts with it shown.

## Launch arguments (after `--`)

| Argument | Effect |
|---|---|
| `--tile-url=<url>` | PMTiles URL; empty = synthetic city |
| `--time=HH:MM`, `--date=MM-DD`, `--time-speed=<x>` | start local time, date (non-leap 2026), simulated seconds per second |
| `--night=<0..1>` | pin the night factor (turns the override on) |
| `--autopilot=<m/s>`, `--autopilot-climb=<m/s>` | level flight north at 300 m AGL / climb-descend cycle 100..8000 m |
| `--max-speed=<m/s>` | optional speed cap for the free-fly camera and the autopilot (no cap by default; the game sets its own; streaming budgets are tested up to 250 m/s, faster flight can show holes) |
| `--cam-alt=<m>`, `--cam-pitch=<deg>`, `--cam-yaw=<deg>`, `--cam-xz=<x>,<z>` | camera start altitude, pitch, yaw (0 = north, positive = left) and local x/z in meters (x east, z south); synthetic city landmarks sit at about castle (100, -169), tower (233, -169), ruin (100, -36) |
| `--view=<fovdeg>,<H>` | override what `WorldView` sends with `set_view` (api 1.10, screen-space LOD; `WorldView.SetViewOverride`): vertical fov in degrees and viewport height in pixels, either part may be empty (`--view=30,2160`, `--view=,540`). `LodPixelScale` is not applied to an override. Headless runs and every `*-selftest` / `--geodetic-test` / `--shot` run pin it to 60 deg / 1080 px unless `--view=` is given (a headless window is about 64 px tall and would make the screen-space edges tiny; `BenchArgs.PinViewForTests`); interactive runs use the real window. Needs a 1.10 library; on api 1.7 the host logs one `set_view unavailable` line and sends nothing. The F1 overlay `view:` line shows fov_y, H, set_view calls, `tau_eff`, the quality, the live edges, the blend distance D and the data tile counters |
| `--render-scale=<0.25..2>` | sets the root viewport's `Scaling3DScale` (like the project setting `rendering/scaling_3d/scale`); `set_view` then carries the 3D render height (viewport height x scale), e.g. 648 -> 324 at 0.5 (`[WorldView] set_view ... render height` log line, F1 `view:` line, `--latency-log` `view:` line). Not for `--shot` / headless runs, which pin the view |
| `--memory-budget-mb=<MiB>` | `WorldRenderSettings.MemoryBudgetMb`: passed as profile override `memory.budget_mb` unless `--set=memory.budget_mb=` / the profile file sets it (224 = the mobile default; desktop default 0 = the library's 512) |
| `--pool-trim-hold=<s>` | `WorldRenderSettings.PoolTrimHoldS` (default 30): seconds the free list of a tile pool must stay above its margin before idle node sets are destroyed; 0 = never. `[PoolTrim]` log lines, pool sizes in the F1 overlay and `--latency-log` |
| `--cam-fov=<deg>` | camera vertical fov at start (also the base of the Z zoom) |
| `--tonemap=filmic\|agx`, `--no-exposure`, `--no-glow`, `--glow-blend=<mode>` | night-look tests |
| `--shot=<png>[,<frames>]`, `--shot-hud` | save the viewport after N frames (default 90) and quit; HUD hidden unless `--shot-hud` |
| `--light-alpha=<x>`, `--fake-fade=<x>` | debug: sprite alpha, fixed fade when Rust has no `poll_fades` |
| `--curvature=<x>` | visual earth curvature: 0 flat, 1 real Earth (default), e.g. 50 to see it clearly |
| `--settings-open` | start with the settings panel (F3) visible, e.g. for screenshots |
| `--overlay-detail` | start with the detailed overlay (F1) on |
| `--settings-selftest` | `SettingsMenu` self-check without input: after the first tiles plus 3 s it drives the panel widgets (speed slider/box/wheel mirror, auto-apply), then applies config A (max distance 6000, detail 0.5, R1 min height 8, lights from R1) and B (defaults) alternately 11 times (`--settings-selftest-applies=<n>`, 4..500, for a leak run: prints the scene node count, pool sizes per apply and fails if the node count grows after the first four applies) with the camera moved between applies and flown off the origin first, checks per apply that the camera is back at x/z 0 with the same geodetic position, no tile is held when the reconfigure finishes, the effective profile matches, the pool in use equals the cover and the host holds what the library delivered; then a rejected out-of-range profile must leave the world untouched and revert the panel. | `--latency-log=<s>` | `LatencyLog`: print the library's streaming latency table (`debug_stats()["latency"]`, api 1.3: per band p50/p95/max ms of `queue`, `fetch_disk`/`fetch_net`, `mesh_wait`, `mesh`, `cpu`, `deliver`, `total`, `swap`) plus the host's per-ring upload ms every N s and on exit. Measuring run: `$G --headless --path . --quit-after 3600 -- --autopilot=250 --latency-log=10`. The same table is in the F1 overlay |
| `--terrain-collision` | turn on the addon's ground collision (`WorldView.TerrainCollisionEnabled`, implies `--terrain`): a 33 x 33 `HeightMapShape3D` patch under the camera from `ground_height_at` |
| `--terrain-collision-selftest` | `TerrainCollisionSelfTest`: 49 rays down hit within 0.1 m of `ground_height_at` at the start, after 3 km and after 6 km (origin shift); off = no body; prints `TERRAIN COLLISION SELFTEST PASS/FAIL`. `$G --headless --path . -- --tile-url= --terrain-collision-selftest` (about 10 s) |
| `--debug-checks` | turn the addon's debug checks on (`WorldRenderSettings.DebugChecks`: the periodic cover verification every 5 s and the first-tile `debug_stats` print). | `--upload-microbench` | `UploadMicroBench` (windowed): times `ArrayMesh.AddSurfaceFromArrays` of a synthetic 20000-vertex tile and variants (no normal, no colour, no uv, vertex only, compress flag, dynamic update) plus the managed copy of a vertex array, prints a table and quits. Measured (M2 Pro, Metal): full 0.93 ms, no NORMAL 0.33 ms (the octahedral normal encode is two thirds of the engine's upload cost), compress attributes 1.9 ms (slower), dynamic update 0.98 ms |
| `--cover-selftest` | run the visibility-rule self-test (`CoverSelfTest`) at startup: the vector layer (z13..z16) and the terrain layer (z10..z14, five rings, `TerrainPool`), each with its own root zoom, and the landmark layer's flat set (api 1.11, `LandmarkCover`, random add / replace / remove / shift over a private `TilePool`); prints PASS/FAIL per layer. Prints `COVER LIVE CHECK PASS/FAIL: ...` and quits with exit code 0 / 1 (simulation result included) |
| `--no-building-lights`, `--pool-max-ring=<n>`, `--glow-levels=<1..4>` | low-tier / measuring switches: `WorldRenderSettings.BuildingLightSprites` off (no building light points: street lamps, beacons and airport lights stay), `WorldRenderSettings.StreetPoolMaxRing` (default 1; -1 = no pools), `NightLook.GlowLevels` (4 = the desktop look with the 1/16 level, 3 = one bloom pass less for a phone) |
| `--no-terrain` | the bench now starts WITH the terrain layer by default (interactive runs; self-tests and `--geodetic-test` stay flat unless `--terrain` is given); this switches it off |
| `--terrain` | turn the terrain layer on (api 1.5; `WorldView.EnableTerrain` + `TerrainEnabled`, i.e. the `layers` option and profile `terrain.enabled`); needs a 1.5 library. Raises the camera far plane to the last terrain band edge x 1.15 (149.5 km), drops the scene's fallback plane to y = -30 m, keeps the free-fly camera above the terrain (min 10 m AGL; the level autopilot holds its height above ground), and with `--curvature` < 1 turns the real-size horizon cull off. Day fog reaches the far bands (`NightLook.TerrainDayFog*`). Without it (and with `--no-terrain`, or in a self-test) nothing terrain-related runs. The F3 panel can switch it at run time |
| `--terrain-detail=<x>` | `set_terrain_detail(x)` after start (implies `--terrain`). Since api 1.10 `x` is a SCALE of the terrain cover's screen-space-error threshold (tau = `terrain.tau_px` x x): above 1 is coarser (fewer, larger tiles), below 1 is finer and much more expensive (0.25, the minimum, is about 2300 tiles); the library clamps to [0.25, `terrain.detail_scale_max`] (2). This is the raw library scale; the F3 "Terrain detail" slider shows 1 / scale. Nothing is re-meshed or re-delivered, the cover changes through ordinary swaps |
| `--no-engine-surfaces` | `WorldRenderSettings.EngineSurfaces` = false (api 1.11, contract 4a): the library does not pack the meshes in Godot's vertex layout on its workers; Godot packs the `Mesh.ARRAY_MAX` Arrays on the main thread, as before 1.11. A/B for the upload markers. Default: on with a 1.11 library |
| `--no-landmarks` | do not opt in to the landmark layer (api 1.11; `WorldView.LandmarksEnabled` = false): the landmarks (roof of 60 m or more) of a two-level archive stay folded into the vector chunks of every band and no `l/z/x/y` key arrives. Default: on with a 1.11 library (a landmark tile per overview tile, flat set, no fades) |
| `--terrain-amplitude=<m>` | profile `terrain.amplitude_m` (default 450 m since the relief was made more visible; 900 with `--set=terrain.feature_size_m=5000` shows snow caps and rock) |
| `--terrain-reach-km=<x>` | shorten the terrain layer: keeps the default bands whose inner edge is below the reach, clamps the last edge to it and moves `terrain.far_zoom` (fewer tiles / draw calls, e.g. 25 = T0..T2) |
| `--far=<m>` | camera far plane (default: the scene's 30 km, or with terrain the reach x 1.15) |
| `--terrain-log` | log the terrain layer once a second: held / visible per ring, uncovered roots (holes), tiles shown at fade 0, camera against the terrain |
| `--churn-log` | log every unload (layer, key, how long it was held, fading / visibility at that moment), every fresh delivery of a key unloaded less than 10 s before (`RE-DELIVERY`), origin shifts and reconfigures (`[Churn]` lines, first 400) |
| `--hide-vector`, `--hide-fallback` | screenshot aids: hide the whole vector layer (terrain only) / the fallback plane |
| `--terrain-selftest` | `TerrainSelfTest` (implies `--terrain`; use `--tile-url=`, headless works): pass 1 flies 250 m/s over the hills (300 m, climb to 3000 m, descend; origin shifts) and checks every frame that no terrain tile is visible with a visible ancestor and every held tile has a mesh, periodically the per-layer cover (`VerifyCover`) and that the host's terrain tile map matches `debug_tiles` (equal after settling, also `terrain_loaded`); then the detail phase (api 1.10: the scale moves the cover, nothing is re-delivered; the camera is held still): `set_terrain_detail(2.0)` must settle (nothing pending, held set unchanged 2 s) on fewer or equal tiles with the host map equal to `debug_tiles`, `set_terrain_detail(0.1)` must read back clamped to 0.25 from `debug_stats` `terrain_detail` (it goes straight back to 1.0 in the same frame, never settled at 0.25: that is about 2300 tiles), 1.0 must settle within 15 % of the flight baseline (the cover has hysteresis, so the set after a trip to 2.0 is the one "from below"), and a second 2.0 -> 1.0 trip must return to exactly that set (+-2 tiles, triangles within 1 %); each phase (flight, detail, pass 2) has its own real-time budget; pass 2 reconfigures with the profile enabling terrain but no `layers` opt-in and asserts zero `t/` keys, nodes, `debug_tiles` / `debug_stats` entries and `ground_height_at` 0. Options `--terrain-selftest-speed=<m/s>`, `--terrain-selftest-timeout=<s>` (real-time budget per phase, default 300) |
| `--window-selftest` | `WindowSelfTest` (night windows W4): after `Start()` scrubs the hour 12:00 -> 03:00 (0.05 h steps) through `WorldView.SetTime` and checks that the `window_share` array on both building materials equals the interpolated `lit_share` tables of `world_profile()`, ids 3 5 6 7 stay 0, no share rises after 18:00 (windows only turn off), and that the array is uploaded only when the hour moved by more than 0.01 h (also across the 24 h wrap). ## Night windows (W4, `docs/spec-night-windows.md`)

- `WorldView` reads `lights.profiles.*.windows.lit_share`, `color` and `landmark.floodlight` from `world_profile()` after every configure (`WindowProfile`), sets the profile colours and the floodlight on both building materials (`TilePool.SetProfileColors` / `SetFloodlight`) and, from `SetTime`, the interpolated shares (`TilePool.SetWindowShares`, only when the hour moved by more than 0.01 h). A library without the tables falls back to `TilePool.FallbackWindowShares` and logs a warning. Retune hours, colours or the floodlight with `--profile=` / `--set=` (e.g. `--set=lights.profiles.landmark.floodlight.strength=1.0`), no code change.
- Windows do not bloom (emission `0.65 x EmissionLevel` under the glow threshold `0.82 x`); the landmark floodlight does (`strength 1.2 x EmissionLevel`, brightest at the wall base, fading up over `fade_height_m`).
- **Window / sprite cross-fade:** where a cell is about one pixel the grid is replaced by its average (faint, desaturated, cool: `WorldRenderSettings.WindowAvgGain` / `WindowAvgDesaturate` / `WindowAvgTint`), and that average fades to 0 between `WindowSpriteBlendStartM` and `WindowSpriteBlendEndM` (900..2000 m of view depth, one pair written to the building and the sprite material). The light sprites of R1 (`lights.min_ring` default 1) fade IN over the same range (their quad is collapsed closer than the start), R2/R3 sprites start beyond it. So R0/R1 buildings are lit by windows up close, by sprites far away, never both at full strength. Before this, far R1 blocks (R1 tiles reach to about 3.2 km because tiles are up to 0.7 km wide) glowed tan from the window average on their side walls.
- **Cross-fade follows the live LOD (S3, api 1.10, `WorldRenderSettings.BlendFollowsLod`, default on):** the 900..2000 m window / sprite blend, the 1200..2174 m street light pool fade (end = min(D, D / hysteresis)) and the sprites' 21000..25000 m far fade are written from the library's live `lod_edges_m` (`WorldView.ReadLod`, 4 times a second): with D = the R2 to R1 edge the blend is 0.36 D..0.8 D, the pool 0.48 D..min(D, D / hysteresis) (`TilePool.SetLodRanges`), recomputed when D moves by more than 5 %, and the sprite far fade is 0.84 M..M with M = `bands.max_distance_m` (`TilePool.SetLightFar`), so D = 2500 m and M = 25 km give the old numbers (pool end 2174 m since round 3). The runway marking ring edges follow `lod_edges_m` x (2 - hysteresis) too. Off = the fixed settings values.

## Diagnostics (performance measurement; `scripts/Diagnostics/`, namespace `LowPolyMap.Diagnostics`)

The same approach as the SimPlane game's `Diagnostics/` (copied and adapted: `PerfMonitor`, `PerfStats`, `DurationHistogram`, `PerfMarker`, `JsonText`, the F4 overlay, `--benchmark` / `--soak`, per-machine baselines), so CPU, GPU, memory and draw calls are measured the same way in both projects. Host-only: the addon carries just a small allocation-free timing surface (`StreamerTimings`, `WorldView.Timings.cs`, wrapped around the facade calls).

- **Per frame** (`DiagnosticsNode`, process priority lowest of the scene, created by `BenchArgs`): `PerfMonitor.Frame()` takes the wall frame time (Stopwatch, not Godot's delta), `TimeProcess` / `TimePhysicsProcess`, draw calls, primitives, video and static memory, and the root viewport's measured render CPU / GPU time (`ViewportSetMeasureRenderTime`); it feeds the session stats (mean, p50 / p95 / p99, max, 1 % low, hitches, frames over 33.3 ms), a 1 s window and a 300-frame ring for the graph. **GPU time is 0 on Metal** (Godot 4.7.2 returns no viewport timestamps, same as the game's Forward+ finding): the result says `gpu_frames: 0`; with vsync off the frame time is the cost to compare.
- **Markers** (`PerfMarker`, 0.01 ms histograms and Godot custom monitors `SimWorld/<name>_ms`): `update_camera`, `poll_ready`, `fades`, `unload`, `origin_shift`, `debug_stats` are the main-thread time inside those library calls (the facade measures them for every caller; they are the calls only, not the host work around them), `upload_vector` / `upload_terrain` / `upload_landmarks` are the host upload time per layer (deltas of `WorldView`'s cumulative upload counters), `overlay` is the F1 refresh plus the F4 text and graph. Host work around the calls has its own markers: `unload_apply` (applying the `poll_unload` batch: cover removal, hide, retire), `fade_apply` (parsing and applying the `poll_fades` dictionary, material switches) and `release_drain` (the time-sliced clearing of retired node sets), all from `WorldView.LastUploads`. Nested scopes count twice (the F1 refresh contains its `debug_stats` read).
- **Once a second** (`SecondSampler`): `debug_stats()` `memory_mb` (total, data_tiles, height_tiles), `jobs_queued` / `jobs_running`, `data_tiles_loaded`, tiles loaded per layer and queued, host pool nodes; process memory (`ProcessMemory`: physical footprint through `proc_pid_rusage` on macOS, working set elsewhere, microseconds, no child process), `OS.GetStaticMemoryUsage`, `GC.GetTotalMemory(false)` and the managed allocation rate (`GC.GetTotalAllocatedBytes` delta). Each is a `Series` (min / max / last / mean / least-squares slope per minute).
- **Frame split** (`frame_split` in the result, `frame_ms` / `process_wall_ms` / `render_cpu_ms` / `other_wait_ms` per second): script work = wall time from the first to the last `_Process` of the frame (`DiagnosticsNode` opens the timer, `ProcessTail` closes it), physics and render CPU from Godot's monitors, GPU where the driver reports it, and `other_wait` = what is left (presentation, GPU wait, idle; never below 0). Together with the CPU use below it says CPU-bound or waiting: the result's `verdict` compares the main thread's CPU % with 90.
- **CPU use** (`CpuTimes`, per second, 100 = one core): `cpu_process_pct` (all threads, .NET `TotalProcessorTime`), `cpu_main_thread_pct` (`ThreadClock`: `clock_gettime(CLOCK_THREAD_CPUTIME_ID)`, macOS and Linux), `cpu_other_threads_pct` = process minus main thread = the Rust workers plus Godot's render / audio / GC threads. `debug_stats` does not expose the library's worker CPU, so the two cannot be separated further (the library's own `SIMPLANE_PROFILE=1` log has per-job CPU).
- **Visibility churn** (counters in `TileCover`, per layer, `visibility_churn` and `*_per_s` series): tiles shown / hidden, **quick toggles** (the same tile changed shown/hidden twice within 1 s: the flicker candidates), fades (sibling swaps) started / ended / active, re-deliveries (a key delivered again less than 10 s after it was removed). Landmark tiles have their own cover and are not counted.
- **Uploads** (`uploads`, `upload_*` markers): tiles per layer, frames that uploaded, frames over the upload budget (`WorldRenderSettings.UploadBudgetUs`), tiles per uploading frame, the worst frame's ms. `burst_frames` = frames that ran with the burst budget (a deep backlog and a camera below 60 m/s: `UploadBudget`, `WorldRenderSettings.UploadBudgetBurstUs` 4 ms / 4 tiles; steady flight keeps 2 ms / 2 tiles); `sprite_fill_r<N>_*` = host time to pack and upload the sprites of a tile per ring; `config.fill_s` / `fill_tiles` = the cold fill: seconds into the settle phase of the last tile upload and the tiles uploaded by then.
- **Stalls** (`stalls` in the result, `StallLog`): the GC pause total and the frames with a pause of 1 ms or more; the three longest frames with their GC pause (`GC.GetTotalPauseDuration` delta), the wall AND thread CPU time of every library call (`StreamerTimings.MeasureThreadCpu`; wall far above CPU = descheduled or suspended inside the call, wall equal to CPU = the call worked or a GC ran on that thread) and the `PerfMarker` categories of that frame.
- **Per layer draw proxy**: shown tiles inside the camera frustum and their triangles per layer (`vector_tiles_in_frustum` ..., one mesh instance per tile; sampled once a second, it costs about 1 ms of the 1 Hz part).
- **Noise** (`noise` in the result): load averages and the other busy processes before and after the run (`sysctl vm.loadavg`, `ps`). **Numbers from a loaded machine are noisy and must not become baselines**: `--update-baseline` only on an idle machine (check `noise.before`).
- **Cost of measuring** is in every result (`diagnostics_overhead`: the per-frame part, the 1 Hz part, and `frame_allocated_bytes`, which must be 0).
- **Result** (`BenchmarkReport`, one JSON file): config (path, hour, view, edges, tau, terrain), end state (the same numbers on two runs mean the same path), build (commit and dirty flag, Godot, library version / api / flavour), machine, `perf`, `markers`, `gc`, `diagnostics_overhead`, `series`, for a soak `soak.first_minute` / `last_minute` / `after_first_minute` / `memory_slope_mb_per_min`, and `baseline`.
- **Baselines**: none is committed yet: write them with `--update-baseline` only when the machine is idle (`noise.before.load_avg` below the core count, no browser / build running; the 5 benchmarks take about 8 minutes). `bench_results/baselines/<machine>.json` (machine = `OS.GetModelName()`, here `Mac14-9`) is committed once recorded, one entry per `<benchmark>@<release|debug>` (a debug library is several times slower, so flavours never compare); the rest of `bench_results/` is ignored by the VCS (`.gdignore` keeps Godot out of it). A frame p95 more than 10 % above the entry sets `"regression": true` and warns. Write the entry with `--update-baseline`. Which library runs: the editor binary has the `debug` feature, so `simplane_world.gdextension` loads `macos.debug`; for release numbers run `cargo build --release`, point `macos.debug` at the release dylib for the run and restore it afterwards. The result says `library_flavour` from the library's build marker.
- Measuring run: `$G --path . -- --benchmark=low-250 --seconds=60 --quit --tile-url=http://127.0.0.1:8787/vilnius-v2.pmtiles --cache-dir=user://cache_bench` (a fresh checkout needs `$G --headless --path . --import` once; the first cache fill happens in the settle phase). Soak: `--benchmark=low-250 --soak=600`.
- Limits: the GPU time above; numbers from a machine that runs other work (a second Godot, a build) are noisy; `TimeProcess` reads higher than the frame time (as in the game) and is reported as Godot gives it.

## Light sprites (far light carpet)

- **One points mesh per tile (round 3 of the performance work):** the tile's building lights, street lamps, airport lights and beacons are ONE `PRIMITIVE_POINTS` `ArrayMesh` (`TileNodes.PointsMesh` / `Points`, 20 bytes per light: position, COLOR rgb + weight, CUSTOM0 RGBA8 = brightness scale, kind, index lo / hi), packed by `PointPacker` (padded to 256 vertices, 1024 above 4096; a padding vertex has kind 255 and is not drawn) and drawn by `light_sprite.gdshader` with `POINT_SIZE` (pixels) and `POINT_COORD` (the dot texture): no billboard quad, no MultiMesh, no `InstanceCount` reallocation. The per-kind looks are the uniform arrays `kind_look` / `kind_gate` (`WorldRenderSettings.SpriteKindLook` / `SpriteKindGate`, `SpriteKind`: 0 light, 1 street, 2 airport, 3 beacon); the hashes of the light pattern are seeded by the light's index within its kind (CUSTOM0), so the pattern does not depend on the packing. Spike result and the D3D12 caveat: point size needs Godot's D3D12 point size emulation (PR 112191); unverified here (Metal only). Beacons: kind 3, 4..5 px, blinking (`blink_*` uniforms, `WorldRenderSettings.Beacon*`).
- `light_sprite.gdshader` keeps every sprite 2..3 px and dims it with distance (`ref² / (ref² + d²)`) and with the environment's depth fog (`WorldView.SetLightFog`, set by `NightRenderController` from `NightLook`; fog_disabled + by hand because the blend is additive). Lights also thin out by viewing angle (`WorldRenderSettings.LightGrazeMin/Max`): low down the far carpet ends before the horizon, at cruise nothing is dropped. Do not make far sprites bigger or brighter again: at grazing angles kilometres of lights share one pixel row and additive sums saturate to a white, blooming band.
- Street lamps (api 1.1, profile `lights.street`) are kind 1 of the points mesh (`WorldRenderSettings.StreetLightIntensity`): no window cross-fade (blend range set below zero in `kind_gate[1]`), so they show near and far. Retune with `--set=lights.street.spacing_m=50`, `--set=lights.street.untagged_max_class=0` (only `lit`-tagged roads), `--set=lights.street.min_ring=4` (off).
- Haze: far sprites widen to 7 px between 3 and 15 km at constant energy (soft glow, no stacking), optional altitude thinning (`LightAltKeepMin`, default 1 = off: a dense carpet like aerial photos; 0.55 thins single lights between 800 and 3300 m). Clusters get a fixed per-light offset (35 m) so the 100 m cells do not read as a lattice. `NightLook.ThresholdCruise` (0.35) lowers the glow threshold with altitude, so the carpet blooms from altitude but windows close up do not. `WorldRenderSettings.LightBlur*`, `LightAlt*`.
- Horizon: the night sky horizon colour is the fog colour divided by `SkyEnergyMultiplier` (the sky's ground half and the fogged ground are the plain fog colour), so the sky's flat horizon line does not show as a box edge.
- Colour variety: street lamps are sodium or white LED per road (`lights.street.alt_color` / `alt_share`, Rust, by OSM id); building light sprites get a fixed per-light tint in the shader (22 % cool LED / TV, 14 % amber, the rest the profile colour, +-30 % brightness; `WorldRenderSettings.LightColorVariation` and friends, 0 = profile colours only).
- Beacons (api 1.2, profile `lights.beacons`): red (15 % green, per building) aircraft warning lights from geometry only: roof corners of every building with a roof of 60 m or more, plus a ring every 45 m up the facade. Kind 3 of the points mesh (the old `beacon_light.gdshader` is gone): 4..5 px, blooms, blinks per building (1.5 s, 45 % on, 15 % glow while off; `WorldRenderSettings.Beacon*`). Retune heights with `--set=lights.beacons.min_height_m=60 --set=lights.beacons.level_spacing_m=0`.
- Light pools: `street_light_pool.gdshader` draws a small MultiMesh per tile (`TileNodes.Pools`, one instance per street lamp, `PoolWriter`: capacity only grows, `VisibleInstanceCount`, custom AABB) as flat additive discs `lights.street.height_m` below each lamp (9 m radius, peak 0.22 x lamp colour, under the glow threshold). Only tiles of ring <= `WorldRenderSettings.StreetPoolMaxRing` (default 1) are filled, and the pool is drawn only while the tile's nearest point is within the fade end + 100 m (`TilePool.UpdatePoolRange`, refreshed 4 times a second with the cull margins); the fade is 0.48 D .. min(D, D / hysteresis) with D the live R2 to R1 edge (`WorldView.PoolFadeEndM`; 1200 .. 2174 m at the default view, was 1200 .. 2500). `SpriteMaterials` holds the point and pool materials with their dither variants.
- The point stands on its roof (raised half its size) with a fixed `lift_m` pull, so buildings in front occlude it; a pull that scales with the sprite size defeats the depth test.

## Landmark layer (api 1.11, contract 9b)

- On by default with a 1.11 library (`WorldView.LandmarksEnabled`, `--no-landmarks` turns it off): buildings with a roof of 60 m or more of a two-level archive (`vilnius-v2.pmtiles`, and the synthetic city) arrive as one `l/z/x/y` tile per overview tile (z11), drawn with the building materials, their light sprites and beacons (the sprites cross-fade with the windows like R1: same material), kept in `WorldView.LandmarkCover` and visible from upload until `poll_unload`; never in `poll_fades`. With `--no-landmarks`, a compat archive (`vilnius.pmtiles`) or a seed world nothing changes and no `l/` key arrives (`CoverLiveCheck` asserts it). The picture is the same either way by design (landmarks are drawn exactly once); the draw calls and the F1 `landmarks:` line differ.
- Overlay F1: `data levels:` and `landmarks:` lines. `debug_tiles` lists landmark tiles with `layer` `landmarks` (state `empty` = overview tile without landmarks); the minimap skips them (they are overview-sized).

## World seed (S1, api 1.7; `docs/spec-world-seed.md` 11d)

- Scene `scenes/SeedTwoCities.tscn` = `CitySpike.tscn` with `WorldView.SeedWorld = "res://world/two-cities/world.json"`, `TileUrl = ""`, `CacheDir = ""` (the same camera, overlay, menus, night controller; no tile server needed). Fly it with `$G --path . res://scenes/SeedTwoCities.tscn -- --seed-spot=eyvi --time=22:00`. The world files are `world/two-cities/` (shared with `cargo test`).
- F1 overlay: a `seed:` line with the data source of the finest tile under the camera (from `debug_tiles` `source`), generator version, phases, airport count, nearest airport, the runway marking mesh (airports / quads) and the first load-time warnings of `seed_world_info()`.
- The F3 settings panel keeps a seed world on a reconfigure (the terrain toggle cannot switch the layer off while `SeedWorld` is set; the library would reject it). Settings that restart the world pass the same `seed_world` option; the library reuses the loaded files.
- Colours: seed class colours and the airport surfaces are `WorldRenderSettings.Seed*` (written to the ground AND the terrain material, `seed_palette.gdshaderinc`), runway markings `Marking*`, airport lights `AirportLight*`.
- Drawn runway height (generator 2, contract 9 "Airports"): no drape lift inside fences, the runway is `ground_height_at` + 3 x `ground.rN.lift_step_m` (0.06 / 0.18 / 0.45 / 1.5 m); `WorldView.ComputeRunwayLifts` applies it to the markings (`MarkingRunwayLevel` = 3) and keeps the old drape replay only for a generator-1 library. `--seed-selftest` checks the host lift per ring (1 mm) and the marking mesh y at EYVI / EYKA. Screenshot aids for close runway views: `--seed-spot-out=<m before the threshold, negative = over the runway>`, `--seed-spot-alt`, `--seed-spot-pitch`.

## Gotchas

- Hand-written `.tscn`: node-typed `[Export]`s need `node_paths=PackedStringArray("Prop", ...)` in the `[node ...]` header or they stay null at runtime. Verify by loading the real scene.
- Never `QueueFree` + `new` tiles; use `TilePool`. Never call Rust from other threads.
- Rust cwd rules: run cargo from `../rust/`, never from this folder.
