# Docs index

One entry per document, moved out of `CLAUDE.md` on 2026-10-30. Big documents (`contract.md`, `spec-world-seed.md`, `spec-terrain.md`, `spec-seed-city-pipeline.md`): list the sections with `grep -n "^## " docs/<file>` and read only the ones you need.


- `docs/decision-library-direction.md`: decision note of 2026-10-29 (direction review): scenery engine, not a second game engine; no dynamic backend (static versioned files only); shipping product = curated seed cities, real OSM optional per city; flat country until a DEM exists; feature freeze until SimPlane flies over the seed world; measure on a weak device first; the data formats are the long-lived contract; ground textures now (host only), traffic later and reduced; between cities a thin real country layer (roads ≥ tertiary, settlement points, land-cover mask, real water and coast) plus roadside autogen towns, three real cities clipped, all of Lithuania under 80 MB; comparison with X-Plane / MSFS / Cesium. Read it before proposing a new subsystem, a server or a new data source.
- `docs/spec-simplane-integration.md`: investigation (2026-10-29, no code) of what both sides must prepare before `WorldView` replaces SimPlane's flat `TestWorld`: SimPlane runs Forward+ with a fixed origin at 47 N 8 E and no map feature; blocking items B1-B6 (library-owned frame, `GroundHeightAt` + runway lift, spawn from `airports()`, a seed world scene, addon vendoring, a Forward+ run), library items L1-L7 (none a contract change), SimPlane items S1-S9, a `WorldChecks` acceptance list and the order of work.
- `docs/architecture.md`: overview (in Russian) of the library's mechanics and architecture: layers and crates, the frame loop, the tile pipeline, LOD cover and visibility, floating origin, tile contents, night, terrain, seed world, profile, lifecycle, tests. An introduction only; the contract wins on any detail.
- `docs/spec-library-packaging.md`: how the spike becomes a reusable library (audit, target structure, phases P0-P7, versioning, daylight menu acceptance). Read it before restructuring anything.
- `docs/spike-streamed-osm-city.md`: the full design (LOD rings, data pipeline, light profiles, imagery, daylight, library API, rendering, iOS constraints, budgets, milestones). Source: https://claude.ai/artifact/1Li6b4rWTHqGtKGDYQZE6E. Read it before making architectural decisions.
- `docs/spec-night-rendering.md`: night details (LOD fades, bloom, tone map, exposure, depth precision). Source: https://claude.ai/artifact/HpzXEiRh1VS71asBF2ER4d.
- `docs/contract.md`: **the** `WorldStreamer` contract (methods, call order, ready-tile dictionary, visibility rule and guarantees, fades, encodings, lights, ground, coordinates, planned API with target `api_version`s). The single source; read it before changing either side.
- `docs/spec-tile-cache.md`: replacing the file-per-tile disk cache with one SQLite file per source (design, eviction, tests, phases T1-T3). Built; its "Status and measured results" section has the benchmark (`cargo bench -p simworld-core --bench cache_bench`), the acceptance results and the deviations from the design.
- `docs/spec-terrain.md`: terrain (M9; built procedurally, the DEM design below the design-change note is superseded and not built): Copernicus GLO-30 as Terrarium raster PMTiles, heightfield cache, a second quadtree layer of Delatin TIN tiles with skirts (`"t/z/x/y"` keys), the drape/lift rule for the vector world, profile section `terrain`, `set_terrain_detail`, budgets and phases T0-T4.
- `docs/spec-world-seed.md`: world seed (M10, proposal): synthetic cities from hand-written city JSON files (hex layout, automatic districts, curved streets), airports from OurAirports at their real positions (the hard rule), pre-computed low-poly coast/water, counter-based hash determinism, per-city switch to real PMTiles ("download city"); requires the terrain layer (runway strips and sea/lakes as rules of the height function, terrain COLOR by class), landed as api 1.7 / profile_version 6. **S0 built** (Rust only: `simworld-core/src/seed/` hash, file schemas in `addons/simworld/seed/`, loaders and validation, water index; `simworld-cli seed airports / water / validate`; all core maths through `libm` via `math.rs`; results in the spec's section 11b). **S1 built, Rust side (api 1.7):** `configure_world` option `seed_world` (needs `tile_url` empty, layers `world` + `terrain`, `terrain.enabled`, `terrain.flat_radius_m` = `flat_blend_m` = 0), `seed::{airport, countryside, terrain, world}`: water + countryside ground in all bands (tint in COLOR `g`), airports (runway, strip, taxiway, apron, terminal, hangars, tower, fence; ground class 7 with sub-kind in COLOR `b`, or 6 via `seed.aeroway_class`), `airport_lights`, the water rule and runway strips in the height function (order field -> water -> strips; rivers vector-only; slope cap 1 %), terrain COLOR (`r` = class / 8) in a seed world, `airports()`, `seed_world_info()`, `debug_tiles` `source`; the shared test world `low-poly-map/world/two-cities/` (real LT airports, LT coast + lakes + rivers; JSON only). Results and spec corrections in section 11c. **Not built:** the Godot half of S1 (shader branches, `WorldView.SeedWorld`, `SeedTwoCities.tscn`, `--world=`, `--seed-spot`, `SeedSelfTest`), S2+ (cities, roads, real sources, landmarks, edits).
- `docs/spec-seed-city-pipeline.md`: proposal (revision 2, 2026-10-30, no code) to redesign seed city generation as the four-stage pipeline of Shariatpour et al. 2026, with no hex cells: context (noisy footprint, constraint map, centrality, growth seeds, guides), road growth by the paper's morphologies (organic / grid / radial; faces become superblocks; CityGML 3.0 road objects: sections, intersections, squares, way surfaces), zoning on superblocks and lots with attributes (R3 lights from lots), buildings from shape rules at LoD0-3 (pitched roofs, fenestration); the paper's parameter ranges as defaults; gallery reproducing its Fig. 2 / Fig. 3 / Table 2; phases C0-C8 toward generator 4. Supersedes `spec-world-seed.md` 5.3 and 6.1-6.4.
- `docs/perf-seed.md`: performance rules for seed generation (2026-10-30): weak-device target, budgets per plan level, twelve cheap-path rules, how to measure each phase and the `seed perf` report line, the critic's checklist. Read before any seed phase.
- `docs/plan-seed-generator4.md`: implementation plan for the city pipeline (2026-10-30): which specs and sections apply, the gates (freeze, api 1.12, order, device), spec fixes D1-D7 before their phase, and per phase C0-C8 the subagent, files, sections to read and acceptance tests.
- `CHANGELOG.md`: API history. Update it with every contract change.
