# SimWorld: механика и архитектура

Обзорный документ для тех, кто впервые открывает библиотеку. Он объясняет, **как устроен** SimWorld и **почему** он устроен именно так. Точные правила (имена методов, ключи словарей, кодировки, гарантии) описаны только в [`contract.md`](contract.md). Если этот текст расходится с контрактом, прав контракт. Подробности по отдельным темам есть в спецификациях `docs/spec-*.md`.

Состояние на `api_version` 1.7 (crate 0.5.0).

---

## 1. Что это

SimWorld — это потоковый low-poly мир по данным OpenStreetMap для авиасимулятора SimPlane. Вокруг движущейся камеры (самолёта) библиотека подгружает тайлы, строит из них здания, землю, дороги, ночные огни и рельеф, а Godot всё это показывает.

Главный принцип: **Rust владеет миром, Godot его только отображает.** Всё, что касается решений (какие тайлы нужны, какой детализации, когда менять LOD), а также генерация геометрии выполняются в Rust. Хост (Godot/C#) загружает готовые меши в GPU, применяет правило видимости и рисует.

```
 ┌───────────────────────────── Godot (main thread) ─────────────────────────────┐
 │  Хост-игра / тестовый стенд (low-poly-map/)                                   │
 │     камера, время суток, UI                                                   │
 │        │                                                                      │
 │        ▼                                                                      │
 │  Аддон addons/simworld/ (C#, namespace SimWorld)                              │
 │     WorldView ─ WorldStreamerFacade ─ TilePool / TileCover / TerrainPool      │
 │     шейдеры: building_windows, ground, terrain, light_sprite, ...             │
 │        │  GodotObject.Call(...)                                               │
 ├────────┼──────────────────────────────────────────────────────────────────────┤
 │        ▼                                                                      │
 │  simworld-godot (gdext, cdylib)  — WorldStreamer: Node, только конвертация    │
 │        │  типов Godot <-> Rust                                                │
 │        ▼                                                                      │
 │  simworld-core (чистый Rust, без godot) — World, scheduler, fetch, mesher ... │
 └────────┼──────────────────────────────────────────────────────────────────────┘
          ▼  рабочие потоки
     tokio (I/O: HTTP range, PMTiles)   SQLite-кэш (свой поток)   rayon (MVT, меши, огни, TIN)
```

| Слой | Где | Ответственность |
|---|---|---|
| **simworld-core** | `rust/simworld-core/` | Весь мир на чистом Rust: покрытие тайлами, загрузка, кэш, декодирование, генерация мешей, рельеф, seed-мир, профиль, детерминизм. Зависимости от `godot` нет (`cargo tree -p simworld-core \| grep godot` должна быть пустой). |

Нода `WorldStreamer` — тонкая оболочка над `World`: переводит `Dictionary`/`Packed*Array` в Rust-структуры и обратно, `Log` → `godot_print!/warn!/error!`. Собирается как `cdylib` + `staticlib` (потом из неё будет `.xcframework` для iOS). |
| **simworld-cli** | `rust/simworld-cli/` | Headless-утилиты: `validate-profile`, `default-profile`, `seed airports / water / validate`. В фазе P6 добавятся fly/bake/bench. |

Модули `simworld-core/src/`:

| `terrain/` | Процедурная функция высоты (`noise`, `sample`) и TIN-меши Delatin с юбками (`tin`). |
| `seed/` | Seed-мир: файлы мира, аэропорты, вода, сельская местность, правила высоты, детерминированный хэш. |
| `synthetic` | Офлайн-город для тестов (пустой `tile_url`). |
| `worker` | Пулы tokio + rayon, задачи fetch/mesh, единый канал crossbeam обратно в главный поток. |

## 3. Кадр: как хост общается с миром

Хост вызывает `WorldStreamer` **только из главного потока**. Каждый вызов неблокирующий, `update_camera` и `poll_*` укладываются в цель < 0.5 мс. Порядок внутри кадра фиксирован (`WorldView._Process`):

```
1. ground_height_at(cam.x, cam.z)                 → высота над землёй (AGL)
2. update_camera(pos, velocity, agl)              → Rust: принять результаты воркеров,
   (или update_camera_geodetic)                     re-center, пересчитать покрытие,
                                                    продвинуть фейды, поставить задачи
3. take_origin_shift()                            → если ≠ 0: сдвинуть камеру и все корни
                                                    тайлов в этом же кадре
4. poll_ready(1) в цикле                          → загрузить меши в пул (≤ 2 тайла, ≤ 2 мс)
5. poll_fades()                                   → значения fade для шейдеров, видимость
6. poll_unload()                                  → вернуть ноды в пул
```

Тайлы, которые не уложились в бюджет загрузки, Rust держит в очереди до следующего кадра. Хост ничего не решает сам: он не отсекает тайлы по дистанции и не считает LOD. Он только применяет правило видимости по ключам (раздел 5).

## 4. Конвейер тайла

```
 wanted ──► queued ──► fetching ──► meshing ──► ready ──► (delivered, held by host)
   ▲          │ tokio: диск-кэш     │ rayon: MVT decode,        │
   │          │ или HTTP range      │ меш зданий, земля, огни,  │ poll_ready: конвертация
   │          │                     │ (TIN для рельефа)         │ в Packed-массивы на
 scheduler    └─ seed/synthetic/terrain: без fetch, сразу mesh  │ главном потоке
 (cover)                                                         ▼
                                                     unloading ──► poll_unload
```

- **Потоки.** Сетевой ввод-вывод идёт через небольшой runtime tokio, у SQLite-кэша свой поток, CPU-работа выполняется в отдельном пуле rayon. Результаты возвращаются по одному каналу crossbeam. Воркеры создают только обычные Rust-структуры (`TileData`) и **никогда не вызывают API Godot**. Паника в воркере перехватывается и превращается в сообщение об ошибке.
- **Лимиты.** На полосу одновременно идёт не больше 4 загрузок и 2 задач мешинга (значения из профиля). Задачи упорядочены так же, как доставки: сначала самые близкие к камере.
- **Источники данных** (в `debug_tiles` поле `source`):
  - `archive`: свой `.pmtiles` по `tile_url`. Слои `buildings`, `landuse`, `roads`, зумы 13–16. Публичные тайловые серверы OSM не используются никогда.
  - `synthetic`: детерминированный офлайн-город (при пустом `tile_url`).
  - `seed`: генератор seed-мира (раздел 10).
  - `terrain`: тайлы рельефа. Это чистая функция, стадии fetch у них нет.
- **Кэш.** На диск пишутся сырые байты тайлов, по одному SQLite-файлу на URL. LRU-вытеснение по байтам (300 MiB), работа офлайн при «тёплом» кэше. Кэш стирается, если меняется отпечаток архива или схема. **Меши не кэшируются**, поэтому после смены профиля или мешера устаревшая геометрия не появляется. Папку кэша держит эксклюзивная файловая блокировка (`.simworld.lock`).

## 5. LOD: квадродерево и правило видимости

### Полосы

Тайлы выбираются как **покрытие квадродеревом** по **3D-наклонной дальности** от камеры до ближайшей точки «коробки» тайла. Коробка — это след тайла × максимальная высота зданий, а при включённом рельефе ещё и диапазон высот рельефа.

| Полоса | Зум | Дальность | Здания | Земля | Огни |
|---|---|---|---|---|---|
| R0 | z16 | < 0.6 km | полная экструзия | все дороги и площади | окна |
| R1 | z15 | 0.6–2.5 km | упрощённая экструзия | без мелких тропинок | окна + спрайты (кроссфейд) |
| R2 | z14 | 2.5–7 km | объединённые блоки, стены без окон | без класса 6 | спрайты |
| R3 | z13 | 7–25 km | нет | грубая (≥ secondary) | спрайты |

- **Look-ahead.** Для каждой полосы покрытие считается из точки «камера + скорость × 20 с», смещение ограничено половиной радиуса полосы. Поэтому при быстром полёте тайлы впереди запрашиваются раньше.
- **Гистерезис 15 %.** Тайл переходит в другую полосу только тогда, когда отходит на 15 % за границу. Так при висении на месте LOD не дрожит.
- Полоса выбирается **только по дальности**. Правил по высоте полёта нет ни в Rust, ни у хоста.

### Sibling swap

При уточнении родитель всегда заменяется **всеми 4 детьми сразу** (группа siblings), а при огрублении — наоборот. Поэтому две стороны любой замены отличаются ровно на один зум, и нет ни дыр, ни перекрытий. Гарантии Rust:

1. Запрашиваются все 4 ребёнка одной группой.
2. Каждый запрошенный тайл доставляется, даже пустой, поэтому группы всегда завершаются.
3. Родитель выгружается только после того, как доставлены все дети и закончился фейд.
4. Тайл выдаётся, только когда его родитель «присутствует» и не участвует в фейде. Поэтому каждый тайл участвует не больше чем в одном фейде одновременно.
5. Первое заполнение (после телепорта) растёт наружу от камеры: корень → лист за несколько кадров, без фейдов.

### Правило видимости (хост, только по ключам)

- Тайл **присутствует**, если он загружен или присутствуют все 4 его ребёнка.
- Тайл без записи в `poll_fades` **виден** тогда и только тогда, когда он загружен, (z == корень или присутствуют все 4 siblings) и присутствуют не все 4 ребёнка.
- Тайл с записью в `poll_fades` виден всегда, пока загружен: обе стороны замены показываются одновременно.
- Новый тайл скрыт, пока после его загрузки хотя бы раз не отработал `poll_fades`.

`TileCover` (C#) и `scheduler::sim::GodotSim` (Rust) реализуют одно и то же правило. Тесты и `--cover-selftest` сверяют их.

### Дизеринговые фейды

Замена не мгновенная. Rust выдаёт `fade` 0..1 для входящей и выходящей стороны, их сумма **ровно 1** (квант 1/256). Шейдер `lod_dither.gdshaderinc` отбрасывает пиксели по матрице Байера 4×4: `fade_parity = z & 1` у двух сторон разная, поэтому они закрывают взаимодополняющие пиксели. Fade зависит **от дальности, а не от времени**: если зависнуть, переход замирает. Через `fades.cap_s` (0.75 с) Rust завершает его принудительно. Одновременно идёт не больше `fades.max_active` = 4 фейдов: discard отключает HSR на тайловых GPU Apple. Остальные замены происходят без фейда.

## 6. Координаты и плавающий origin

- Локальная система совпадает с осями Godot: **x = восток, y = вверх (м над уровнем моря), z = −север**, метры.
- Внутри Rust вся математика в f64 в фиксированной ENU-системе. Хосту отдаются f32 **относительно текущего origin**. Позиции мешей заданы относительно центра тайла (`origin`, y = 0).
- Когда камера уходит от origin дальше чем на **5 km** по горизонтали, `update_camera` переносит origin на камеру (только сдвиг, без поворота). Сдвиг отдаётся один раз через `take_origin_shift()` и сигналом `origin_shifted`. Хост вычитает его из камеры и корней всех тайлов **в том же кадре**. Так точности f32 хватает на любой дальности полёта.
- Для полётной модели есть `update_camera_geodetic(lat, lon, alt_msl, vel_ned)` и конверсии `geodetic_to_local` / `local_to_geodetic`.
- Кривизна Земли **только визуальная**: каждый мировой шейдер опускает вершины на d²/2R от камеры (`earth_curve.gdshaderinc`, глобальные uniform'ы `simworld_curve_*`). Rust, физика и AGL считают мир плоским.

## 7. Что внутри тайла

`poll_ready` отдаёт словарь (полная форма в контракте, раздел 4). Каждый меш — это массив `Mesh.ARRAY_MAX`, его можно сразу передать в `ArrayMesh.AddSurfaceFromArrays`.

### Здания (`mesh`)

Один объединённый меш на тайл R0–R2, то есть один draw call. Здания обрезаются точно по прямоугольнику тайла, поэтому 4 ребёнка покрывают ровно ту же геометрию, что и родитель. Стены — плоские квады, крыши — earcut-полигоны с дырами.

Вершинный **COLOR** несёт данные для шейдера:

| Канал | Смысл |
|---|---|
| `r` | id светового профиля / 8: residential, office, retail, industrial, civic, landmark, dark |
| `g` | сид из хэша OSM id (рисунок горящих окон) |
| `b` | высота этажа / 10 м |
| `a` | высота крыши / 400 м |

**UV стен** задаются в единицах окон: `u` — колонки окон, `v` — этажи. Кольцо делится на «прогоны» по углам (> 35°), в каждом прогоне `round(L / width_m)` колонок, поэтому окно никогда не заворачивает за угол. У глухих стен (промышленные, landmark, dark, `windows=no`, все стены R2) `u = −1`.

### Земля (`ground`)

Один плоский меш на тайл: площади landuse/парков/воды и буферизованные полосы дорог. COLOR кодирует класс (`r`), освещённость дороги или оттенок площади (`g`), класс дороги или подвид аэродрома (`b`). Против z-fighting слои поднимаются ступенькой по уровню укладки (0.02 м на R0 … 0.5 м на R3). При включённом рельефе земля **драпируется**: высота рельефа + `lift(band)` + уровень × шаг. Длинные рёбра дробятся, где рельеф отклоняется.

### Огни

| Ключ | Что | Где |
|---|---|---|
| `lights` | одна точка на здание (центроид, высота крыши) | R1–R3 |
| `street_lights` | фонарь каждые 35 м вдоль освещённых дорог | все полосы |
| `beacon_lights` | красные/зелёные заградительные огни на зданиях ≥ 60 м, `a` = фаза мигания | все полосы |
| `airport_lights` | огни ВПП/рулёжек seed-мира | все полосы |

**Световой ковёр.** Выше ~3000 м AGL (вкл. при 3300 м, выкл. при 2700 м) огни кластеризуются в ячейки 100 м. При смене режима Rust **повторно доставляет** уже загруженные тайлы под тем же ключом, не больше 1 за кадр. Хост заменяет данные на месте.

## 8. Ночь

- **Окна** (`building_windows.gdshader`). Процедурная сетка из `floor/fract(UV)`, целочисленный хэш от COLOR `g/b/a`. Доля горящих окон по часам (`lit_share`, 24 значения на профиль) берётся из `world_profile()`, `WorldView.SetTime` загружает её в материалы. Окна не дают bloom, их эмиссия ниже порога glow.
- **Кроссфейд окна ↔ спрайты.** Там, где ячейка окна около пикселя, сетка заменяется своим средним. Среднее гаснет на глубине 900..2000 м, а спрайты R1 на том же отрезке проявляются. Вблизи здание освещают окна, вдали спрайты, и никогда оба на полную силу.
- **Спрайты** (`light_sprite.gdshader`): 2–3 px, тускнеют с расстоянием и туманом, прореживаются под скользящим углом. Ограничение намеренное: далёкие спрайты нельзя делать крупнее, иначе у горизонта аддитивная сумма выжигается в белую полосу.
- **Landmark** получает подсветку основания (floodlight), которая даёт bloom. **Dark** (руины, сараи) — без окон и без световой точки.
- **Огни тайла** (окна издалека, фонари, огни аэродрома, маяки) — один меш из точек (`PRIMITIVE_POINTS`, по вершине на огонь, `light_sprite.gdshader`, `PointPacker`); вид задаётся «видом» огня в CUSTOM0. **Пятна света** фонарей на земле (`street_light_pool.gdshader`) — небольшой MultiMesh только у тайлов R0/R1 в пределах затухания. **Маяки** мигают в том же шейдере (вид 3).
- Глобальный `simworld_night_factor` и часы задаёт хост (`TimeOfDay` в стенде). Солнце, экспозиция, tone map и небо — политика хоста. Аддон даёт `NightLook` (glow, туман).

## 9. Рельеф (M9)

- **Процедурный, без данных.** Функция высоты — сидированный value noise в f64 на целочисленном хэше (гребни, долины, плато, уровень моря, плоская зона вокруг `terrain_center`). Это чистая функция от профиля, центра и точки, поэтому результат побитово одинаков в любом потоке и при любом порядке вызовов.
- **Одна функция для всего.** `ground_height_at`, основания зданий (по самому низкому углу следа) и фундаменты, драпировка земли, высоты огней и коробки покрытия используют одну и ту же функцию высоты.
- **Второй слой квадродерева.** Ключи `t/z/x/y`, зумы 10..14, полосы T0–T4 до 130 km. Меш — TIN Delatin (жадная вставка до `max_error_m × detail`) с вертикальными юбками, которые закрывают трещины между соседями. Отсечение по горизонту не запрашивает тайлы, скрытые кривизной Земли. Слой подчиняется тем же гарантиям, фейдам и правилу видимости, у хоста отдельная карта тайлов (`TerrainCover`/`TerrainPool`).
- **Lift-правило.** Земля векторного слоя поднята над функцией высоты на худшую ошибку TIN, который может быть виден на этой дистанции (R0 1 м … R3 20 м). Поэтому дороги не уходят под меш рельефа ни при каком `set_terrain_detail`.
- Включается явно: `layers: ["world","terrain"]` + `terrain.enabled`. Фактическое состояние показывает `status()["terrain_active"]`. Опционально `TerrainCollision` строит патч `HeightMapShape3D` 33×33 под камерой.

## 10. Seed-мир (M10, фаза S1)

Seed-мир — это мир, собранный целиком из рукописных JSON-файлов (`world.json`, города, аэропорты, вода), без тайл-сервера.

- **Аэропорты** (из OurAirports, на реальных координатах): ВПП, полоса безопасности, рулёжки, перрон, терминал, ангары, вышка, забор, огни. Земля класса 7 с подвидом в COLOR `b`.
- **Вода и местность**: море и озёра из полигонов, поля/луга/лес патчами с оттенком.
- **Правила высоты** поверх рельефа, по порядку: поле → вода (море и каждое озеро плоские) → полосы ВПП (линейно между порогами, уклон ≤ 1 %, ровно поперёк). Поэтому ВПП ровная, а море плоское во всех выходах сразу.
- Детерминизм обеспечивается счётными хэшами, квантованными входами и `libm`. Генерация не зависит ни от кадра, ни от origin.
- На стороне хоста: `WorldView.SeedWorld`, `Airports`, `SeedInfo`, разметка ВПП (`AirportMarkings`), сцена `SeedTwoCities.tscn`. Города и дороги появятся в фазах S2+.

## 11. Профиль мира: тюнинг — это данные

Всё настраиваемое вынесено в JSON-профиль: границы полос, гистерезис, допуски Douglas–Peucker, минимальные площади и высоты, параллелизм, кэш, световые профили, таблицы дорог и площадей, рельеф, seed. Структурные вещи остаются константами: 4 полосы, зумы 13–16, имена слоёв, кодировки COLOR.

- `addons/simworld/profiles/default.json` перечисляет все ключи со значениями по умолчанию, `world-profile.schema.json` задаёт диапазоны и единицы. Тесты сверяют оба файла с кодом.
- Хост передаёт `profile_path` и/или `profile_overrides` в `configure_world`: объекты сливаются глубоко, массивы и скаляры заменяются. Ошибка валидации ничего не меняет, а сообщение называет ключ, значение и допустимый диапазон.
- `profile_version` (сейчас 6): файлы своей или более старой версии проверяются строго (неизвестный ключ = ошибка), более новые загружаются с предупреждениями.
- `world_profile()` отдаёт итоговый профиль хосту, например для шейдеров окон.

## 12. Жизненный цикл

- **Одна нода = один мир.** Можно держать несколько инстансов в процессе (например, основной вид и карту), у каждого свои потоки и своя папка кэша.
- `configure_world` — это **телепорт**: старые воркеры останавливаются (с ожиданием кэша до 1 с), все загруженные ключи приходят в ближайший `poll_unload`, origin сбрасывается. При ошибке ничего не меняется и старый мир продолжает работать.
- `shutdown()` останавливает мир и освобождает блокировку кэша, нода становится инертной до следующего configure. До configure и после shutdown все методы — безопасные no-op.
- `status()` / `status_changed`: `ok` / `degraded` (сервер недоступен, но отдаётся кэш; сбои загрузки) / `offline` / `error` (архив не соответствует контракту тайлсета).
- Атрибуция `© OpenStreetMap contributors` (`attributions()`) обязательна, пока на экране есть данные карты.

## 14. Версионирование и тесты

- **Контракт** — `docs/contract.md`, `api_version` major.minor. Минорная версия добавляет, мажорная ломает. Любое изменение контракта в одном коммите обновляет контракт, `API_MAJOR/API_MINOR` (`simworld-core/src/lib.rs`) и `CHANGELOG.md`. `cargo test` падает, если версия или список `#[func]`/`#[signal]` расходятся с контрактом.
- **Детерминизм**: один и тот же тайл даёт один и тот же меш и те же горящие окна (сид — OSM id), состояния, зависящего от времени, нет. Golden-тесты (`golden_tests`) фиксируют хэши тайлов синтетического города во всех полосах, рельефа, TIN и seed-мира, а также покрытие для фиксированных камер. Пересоздаются только при намеренном изменении: `SIMWORLD_UPDATE_GOLDEN=1`.
- **Rust**: `cargo test` из `rust/` (базовая линия 219 passed). Есть тесты жизненного цикла, профиля, шедулера, кэша (`cache_bench`).
- **Godot**: self-test'ы стенда в headless-режиме (`--cover-selftest`, `--geodetic-test`, `--settings-selftest`, `--terrain-selftest`, `--window-selftest`, `--seed-selftest`, `--terrain-collision-selftest`) печатают `PASS/FAIL` и возвращают код 0/1.

## 15. Ограничения (сводка)

- API Godot никогда не вызывается из рабочих потоков, конвертация в Packed-массивы идёт только в `poll_ready` на главном потоке.
- Крейты Rust живут только в `rust/`, никогда внутри `low-poly-map/`.
- iOS-ready: rustls (без OpenSSL), без desktop-only крейтов, `staticlib`.
- Данные берутся только из собственного `.pmtiles` (planetiler, `data/`), никогда с публичных тайловых серверов OSM.
- Ноды пулятся, их не освобождают и не создают заново на каждый тайл.
