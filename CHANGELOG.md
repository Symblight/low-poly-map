# Changelog

All notable changes to the SimWorld library (Rust `WorldStreamer` GDExtension plus the Godot-side runtime) and its `WorldStreamer` contract. Versions follow semver. `api_version` (from P2) is the contract major.minor, independent of the crate version, and is listed per release; the contract itself is `docs/contract.md`.

Format: one section per release, newest first. Every contract change (a method, a dictionary key, an encoding, a guarantee) must be listed here, in `docs/contract.md` and in `api_version` (`API_MAJOR`/`API_MINOR`), in the same commit.

## Unreleased

P5 "Addon" (Godot side only; **api_version stays 0.7**: no method, dictionary key, encoding or profile key changed, `cargo test` unaffected). The library's C# runtime and shaders moved from the test bench into `addons/simworld/` (namespace `SimWorld`). A host that drove the old spike code must change:

- `StreamerBridge` is now `SimWorld.WorldView` (`addons/simworld/runtime/WorldView.cs`). The command line, the Vilnius default origin and the `user://tile_cache` default are gone from it: set `OriginLat` / `OriginLon` (no default; the view runs without a world and logs an error until both are set), `TileUrl`, `CacheDir` (default `user://simworld_cache`), `ProfilePath`, `BaseProfileOverrides`, `Camera`, `Settings`, `Curvature` as properties; `AutoStart` (default on) starts it in `_Ready`, else call `Start()`. New: `SetTime(localHour, nightFactor)`, C# event `OriginShifted(Vector3)` (raised after the view applied the shift; shift your own nodes here), `DefaultProfile()`. The test bench's `BenchArgs` node now parses the launch arguments.
- The camera is an `IWorldCameraSource` (position, velocity, AGL, `SetGroundHeight`, `ApplyOriginShift`) or any `Camera3D` (adapter `Camera3DSource`: velocity from position deltas). `WorldView.Camera` is only the `Camera3D` for fov and far plane; `FreeFlyCamera` implements the interface.
- Tuning exports moved into the `WorldRenderSettings` resource (upload budget, tiles per frame, prewarm, verify interval, debug light alpha / fake fade, building / ground / light-sprite material parameters; defaults equal the shaders' own). Bloom and fog moved out of the bench's `NightRenderController` into the `NightLook` resource, which applies them to an `Environment` the host passes in; exposure, tone map, sun and sky stay with the host.
- Shader globals are real global uniforms, registered in the project settings by the addon's editor plugin (`plugin.cfg`) and at runtime by `WorldView` for hosts that did not enable it: `simworld_night_factor` and `simworld_hour` (set by `SetTime`; the night factor was a per-material uniform before, `hour` is not read by a shader yet), and `simworld_curve_center` / `simworld_curve_inv_2r` (were `curve_center` / `curve_inv_2r` in the bench's `project.godot`). `WorldView.NightFactor` is now read-only.
- Assets load relative to the addon (`AddonPaths.Root` from the script's resource path; shader includes are relative). `addons/simworld/simworld.gdextension` lists macOS, Windows x86_64, Linux x86_64 and iOS libraries in `bin/` (built by `tools/build_addon.sh`, not committed). The bench keeps `low-poly-map/simplane_world.gdextension` (loads `rust/target`) as the dev override and gets the addon through `tools/sync_addon.sh` (generated, ignored copy).
- Checked: bench smoke test, `--settings-selftest`, `--geodetic-test`, `--cover-selftest` pass; night and day screenshots look as before; a fresh Godot 4.7 .NET project with only the addon, a `Camera3D`, a `WorldView` and a 20-line clock script renders the synthetic city at day and night, and enabling the plugin in the editor registers the globals with no shader errors. **Not checked:** the minimal iOS export.

Profile version 3 (world profile key only; **api_version stays 0.7**).

- `PROFILE_VERSION` = 3. New key `lights.min_ring` (integer 0..3, default **2**, `docs/contract.md` 3.2 and 8): the finest band that carries light sprites. The default gives bit-for-bit the same output (R2/R3 only; golden hashes unchanged). With 1 (or 0) R1 (R0) tiles also deliver `lights` / `light_colors` (single and clustered, same colors and weights; re-delivered on light-mode switches like R2/R3, and the poll_fades sum rule keeps the brightness constant across a swap). It is a stopgap for the dark near field until the window shader (M6) lights R0/R1: the sprites sit at roof height on top of the building meshes, so turn it back to 2 once windows exist. Test bench: row "Light sprites from band" in the F3 panel, `--set=lights.min_ring=1`.

Profile version 2 (world profile keys only; **api_version stays 0.7**: profile keys are additive and versioned by `profile_version`, no method, dictionary key or encoding changed).

- `PROFILE_VERSION` = 2. New keys `buildings.r0.min_height_m`, `buildings.r1.min_height_m`, `buildings.r2.min_height_m` (0..500 m, default 0 = keep all; `docs/contract.md` 3.2): a building whose resolved roof height (tagged `height`, else levels x floor height, else the kind/landuse fallback; top of roof above ground, the same value as COLOR `a`) is below the value is left out of that band's building mesh. Applied per feature before clipping, like `min_area_m2`. Building mesh only: lights (single and clustered), ground, roads, landuse and the tile box height are unaffected. No R3 key (R3 has no building mesh). Defaults give bit-for-bit the same output (golden hashes unchanged). A profile_version 1 file still loads; missing keys keep their defaults.
- `fades.cap_s` default 3.0 -> **0.75** s (range unchanged). The cap force-completes a LOD fade that has not finished by slant distance. With a stationary camera fades do not progress by distance at all, so every refine level waited for the cap: this shortens the wait before finer rings appear (measured on Vilnius data: first R0 tile ~7 s -> ~2-3 s after start). Side effect: a distance-driven fade still in flight after 0.75 s (slow climb or descent through a band edge) is now cut short and completes in one frame, where it used to get up to 3 s; the visual cross-fade can be shorter in that rare case. Set `fades.cap_s` back to 3 for the old behaviour. Scheduler fade tests now fly at 180 m/s so they still test distance-driven fades inside the cap.

Internal: disk tile cache in one SQLite file (`docs/spec-tile-cache.md`, T1-T3). No contract change, **api_version stays 0.7**.

- New on-disk format: `{cache_dir}/tiles-{hash}.sqlite` (WAL, exclusive locking; `rusqlite` with the bundled SQLite, no system library) replaces the file-per-tile folders `pmtiles-v{N}-{hash}/{z}/{x}/{y}.mvt`. `CACHE_SCHEMA_VERSION` = 3. Old folders of the same source (also the unversioned `pmtiles-{hash}/`) are deleted on first open and not migrated: the cache refills from the network. `cache_dir`, `cache.cap_mb` and `debug_stats().cache_mb` keep their meaning. One cache thread owns the connection; writes are batched (250 ms or 64 puts), hits never write (access times go with the next batch), eviction by bytes to 90 % of the cap, then `incremental_vacuum` gives the pages back. The pages in use are also bounded (cap + 5 % + 1 MiB; tiles land at random places of the key B-tree, so pages are ~80 % full), keeping file + WAL within cap + 5 % + 1 MiB + ~4 MiB WAL (321 MiB peak at 300 MiB); a full cache holds ~80-87 % of the cap in tile data (`cache_mb`). Index `tiles_lru(atime, key, size)` covers the byte total at open and the eviction scan. A corrupt file is recreated (info log); a file held by someone else means running without a disk cache (warning); three failed writes in a row turn the cache off for the configuration and set status `degraded` (`disk cache disabled after write failures; streaming without it`, `docs/contract.md` 3.5).
- Measured on the Vilnius archive (30,726 tiles, 61 MB; `cargo bench -p simworld-core --bench cache_bench`): see `docs/spec-tile-cache.md`, "Status and measured results".

P4 "Host API" (`docs/spec-library-packaging.md` section 4, findings A8/A9). **api_version 0.7** (additive: nothing existing changed meaning; golden hashes unchanged).

- New `#[func] update_camera_geodetic(lat, lon, alt_msl_m, vel_ned: Vector3)` (`docs/contract.md` 3.3): WGS84 degrees, altitude above MSL (no geoid model: ellipsoid heights must be converted by the host), AGL = altitude − `ground_height_at` (terrain 0 until a DEM), NED velocity mapped to local x = E, y = −D, z = −N. Same path as `update_camera`, re-centering included. Invalid input (non-finite, |lat| > 90, |lon| > 180) is logged and ignored.
- New `#[func] geodetic_to_local(lat, lon, alt_msl) -> Vector3` and `local_to_geodetic(Vector3) -> Vector3(lat, lon, alt)`: through the current floating origin, usable right after configure. Local `y` = meters above MSL. f64 round trip < 1 cm within 20 km (test); the returned Vector3 is f32 (lat/lon ≈ 4e-6° resolution).
- New signal `origin_shifted(shift: Vector3)`, emitted on the main thread during `update_camera` / `update_camera_geodetic` on a re-center. Same vector as `take_origin_shift()`, which keeps its same-frame semantics and is not consumed by the signal.
- New `#[func] attributions() -> PackedStringArray` (same strings `configure_world` returns; empty for the synthetic city, before configure and after `shutdown`).
- New `#[func] status() -> Dictionary` and signal `status_changed(status: Dictionary)`: `{ state: ok|degraded|offline|error, message, failed_fetches, last_error }` (`docs/contract.md` 3.5). Derived from fetch results: tileset-contract mismatch or worker start failure = error; archive cannot be opened and nothing served yet = offline; archive unreachable with cached tiles served, or any fetch/decode failure in the last `retry_max_s` + 5 s = degraded. The signal fires only when state or message changes, from `update_camera(_geodetic)` / `poll_ready`.
- New `#[func] shutdown()`: stops the workers, waits at most 1 s for in-flight cache I/O (tokio `shutdown_timeout`), releases the cache folder lock; the node is inert until configured again (the tiles held by the host are reported once by the next `poll_unload`). Freeing the node stays a background stop.
- Lifecycle rules (`docs/contract.md` 11a): several nodes per process are supported (no process-global state; test runs two worlds side by side). `configure_world` / `configure` take an exclusive lock on `cache_dir/.simworld.lock` (`std::fs::File::try_lock`) synchronously when `tile_url` and `cache_dir` are set; a held folder gives `ok: false`, `error: "cache_dir in use: <cache_dir>"` and changes nothing. The lock is kept across a re-configure with the same folder (compared canonically) and released on `shutdown`, drop or a `cache_dir` change.
- Teleport ordering fix: a re-configure used to drop the old worker with `shutdown_background()`, so its in-flight disk-cache writes (and the cache index scan) could overlap the new worker's cache open in the same folder. The old worker now stops before the new one starts, with the bounded 1 s wait when it used a disk cache (background stop otherwise).
- Internals: `fetch::FetchError { kind: Unreachable | Contract | Tile, message }` replaces the `String` error of `Fetcher::fetch` / `WorkerMsg::Fetched`; `Worker::shutdown(wait)`; new core modules `lock` (`FolderLock`) and `status` (`Health`, `Status`, `StatusState`); `World::update_camera` returns the shift it applied. Guard tests: 18 `#[func]`, and every `#[signal]` must appear in `docs/contract.md`.

P3 "Config" (`docs/spec-library-packaging.md` section 3). **api_version 0.6** (additive: nothing existing changed meaning; default output is bit-for-bit the same, pinned by golden hashes).

- New `#[func] configure_world(options: Dictionary) -> Dictionary` (`docs/contract.md` 3.1): keys `origin_lat`, `origin_lon`, `tile_url`, `cache_dir`, `profile_path`, `profile_overrides`, `diagnostics` (`profile`, `warnings_per_second`); result `{ ok, error, api_version, attributions }` (`["© OpenStreetMap contributors"]` for a `tile_url` source, empty for the synthetic city). Everything is validated first; on an error nothing changes. Unknown option keys are warnings.
- New `#[func] world_profile() -> Dictionary`: the resolved world profile (defaults until a `configure_world` with a profile).
- `configure(lat, lon, tile_url, cache_dir)` is now a wrapper over `configure_world` with the default profile. Same signature, return type, log line and teleport behaviour. New: an origin outside ±85.05° / ±180° or a `tile_url` that is not `http(s)://` is rejected with a logged error, and the previous configuration keeps running. Before, such values were accepted and failed later, or produced garbage.
- World profile (`docs/contract.md` 3.2): every tuning value (audit A6) is data in `simworld_core::profile` (`WorldProfile`, `Profile`, `PROFILE_VERSION` = 1), with `addons/simworld/profiles/default.json` (all keys = the compiled-in defaults) and `world-profile.schema.json` (units, ranges). `cargo test` checks that `default.json` equals `WorldProfile::default()`, and that the schema documents the same keys and ranges as the core. Partial profiles and deep-merged overrides are supported. An unknown key is an error at the library's `profile_version` or older and a warning for newer versions. Out-of-range values are rejected with key, value and range.
- Tileset contract check (audit A18): when a `.pmtiles` archive opens, its header must cover z13-16 and its metadata must list the `buildings`, `landuse` and `roads` layers. Otherwise an error is logged once and its fetches fail. Ring count and zooms stay compiled-in constants.
- Determinism (audit A16): `simworld-core` `golden_tests` pins FNV-1a hashes of the real tile build path for 8 synthetic-city tiles (2 per band, ground on R0-R2, lights on R2/R3). Positions are quantized to 1 mm, colours and normals to 8 bits, and per-building output is sorted by OSM id. The tests also pin the cover (tiles requested) for 4 fixed cameras. Regenerate with `SIMWORLD_UPDATE_GOLDEN=1 cargo test -p simworld-core golden -- --nocapture`. A scenario test shows that `bands.r0_edge_m = 250` changes the cover: R0 tiles at 300 m AGL go from 16 to 8.
- `simworld-cli validate-profile <file>` prints `OK` (exit 0) or the error (exit 1). This is the core's own check, not a generic JSON Schema validator. `simworld-cli default-profile` prints the defaults.
- Internals: module constants moved into the profile (`BAND_EDGE_M`, `HYSTERESIS`, `LOOK_AHEAD_S`, `DEFAULT_TILE_HEIGHT_M`, `R*_PARAMS`, `R*_GROUND`, `MAX_FETCH_PER_RING`, `MAX_DECODE_PER_RING`, `CLUSTER_ON/OFF_AGL_M`, `CLUSTER_CELL_M`, `FADE_CAP`, `RECENTER_DISTANCE_M`, `REDELIVERIES_PER_FRAME`, `CACHE_CAP_BYTES`, `OPEN_RETRY_MIN`, `VALIDATE_RETRY`, the HTTP timeouts, the backoff, the light colours and kind lists, and the road/area tables). Core functions take `&Profile` / `Arc<Profile>` (`Scheduler::new`, `Worker::new`, `build_tile`, `mesh_tile`, `mesh_ground`, `resolve`, `LightSet::from_buildings`, `decode_tile`, `Fetcher::new`). New dependencies: `serde`, `serde_json` (pure Rust).

P2 "Contract" (`docs/spec-library-packaging.md`). **api_version 0.5** (introduced; additive only, nothing existing changed).

- `docs/contract.md` is the single statement of the `WorldStreamer` contract: methods and call order, ready-tile dictionary, visibility rule and guarantees, fades and dither rule, vertex/ground COLOR and UV encodings, lights, ground, coordinates, data source, determinism, and the planned API with target versions (0.6 configuration, 0.7 host API and lifecycle, 0.8 daylight, 0.9 imagery). It records behaviour the old copies left out (no-fade exceptions, `update_camera` ignoring `local_pos.y`, horizontal re-center distance, tile-local roof UVs, profile id 5 never emitted). The copies in `.claude/agents/*.md` are replaced by a pointer to it.
- New `#[func] api_version() -> Vector2i(major, minor)` on `WorldStreamer` (currently `(0, 5)`); callable before `configure`.
- `debug_stats()` gains `api_major` and `api_minor` (int), same values.
- `simworld_core::API_MAJOR` / `API_MINOR` constants. Two new tests pin them to the `api_version:` line of `docs/contract.md` and check that every `#[func]` is documented there (`cargo test`: 68 passed).

P1 "Core split" (`docs/spec-library-packaging.md`). No contract change: the 9 `#[func]` methods, their signatures and every dictionary key are unchanged.

- `rust/` is a Cargo workspace: `simworld-core` (rlib, no `godot`), `simworld-godot` (cdylib + staticlib, the `WorldStreamer` node), `simworld-cli` (placeholder). The library file is now `libsimworld_godot.*` (was `libsimplane_world.*`); `low-poly-map/simplane_world.gdextension` keeps its name and `entry_symbol = "gdext_rust_init"`, only the library paths changed.
- `debug_stats()["version"]` (display string) now reads `simworld-godot 0.5.0 (build ...)` instead of `simplane_world 0.5.0 (build ...)`; the `configure` log line shows the same label.
- New core types: `World` (floating origin and re-center, re-delivery pacing, warning rate limit, profiling; the logic that was in `streamer.rs`), `Log` trait, `Diagnostics`. The core reads no environment variables; the Godot binding maps `SIMPLANE_PROFILE=1` onto `Diagnostics` when the node is created (it used to be read on each `configure`).

## 0.5.0-spike (2026-10-26)

First baseline: the spike as built, at milestone M5 and partway through M6. Crate `simplane_world` 0.5.0 (gdext 0.5.5, `api-4-7`, Godot 4.7). There is no `api_version` yet; `debug_stats()["version"]` is a display string only.

### API: `WorldStreamer` (Node, registered by the GDExtension; entry symbol `gdext_rust_init`)

Methods (all `#[func]` in `rust/src/streamer.rs`). Per-frame call order: `update_camera`, `take_origin_shift`, `poll_ready`, `poll_fades`, `poll_unload`. Coordinates: Y-up, x = east, z = -north, meters, relative to the current floating origin.

| Method | Description |
|---|---|
| `configure(origin_lat: f64, origin_lon: f64, tile_url: String, cache_dir: String)` | Sets the origin and data source and (re)starts the workers. Empty `tile_url` = deterministic synthetic city. Re-calling it drops the old scheduler; everything already delivered is returned by the next `poll_unload`. |
| `update_camera(local_pos: Vector3, velocity: Vector3, alt_agl_m: f64)` | Every frame. Recomputes the quadtree cover (3D slant distance, look-ahead, hysteresis) and queues jobs. Triggers a floating-origin re-center when the camera is more than 5000 m from the origin. |
| `poll_ready(max: i32) -> Array<Dictionary>` | Finished tiles, at most `max` (the bridge asks for 2). Every requested tile is delivered, even when empty. Light re-deliveries (clustering above ~3000 m AGL) are limited to 1 per frame. |
| `poll_unload() -> PackedStringArray` | Tile keys (`z/x/y`) to remove. |
| `poll_fades() -> Dictionary` | Key (`z/x/y`) to `fade` (float 0..1) for every tile in a LOD transition. Incoming tiles go 0 to 1, outgoing 1 to 0, summing to 1. Driven by slant distance, force-completed after 3 s. Tiles not listed have fade 1. |
| `take_origin_shift() -> Vector3` | Non-zero once after a re-center; the host subtracts it from the camera and all tile roots in the same frame. |
| `debug_stats() -> Dictionary` | `queued`, `fetching`, `meshing`, `loaded` (each `PackedInt32Array` of length 4, indexed by ring), `cache_mb` (float), `origin_lat`, `origin_lon` (of the current local origin), `version` (String, e.g. `simplane_world 0.5.0 (build debug @...)`). |
| `debug_tiles() -> Array<Dictionary>` | One entry per tracked tile: `key`, `ring` (0..3), `state` (`queued`, `fetching`, `meshing`, `ready`, `failed`, `unloading`), `min`, `max` (`Vector2`, tile rect corners in local x/z meters). |
| `ground_height_at(local_x: f64, local_z: f64) -> f64` | Terrain height (m) under a local x/z point, through the current floating origin. Returns 0 (no DEM yet). |

Ready-tile dictionary (`poll_ready`): `key` (String `z/x/y`), `ring` (int 0..3, = 16 - z), `origin` (Vector3), `mesh` (Array in `Mesh.ARRAY_MAX` layout: VERTEX, NORMAL, COLOR, TEX_UV, INDEX; empty for R3 and empty tiles), `ground` (Array in `Mesh.ARRAY_MAX` layout: VERTEX, NORMAL, COLOR, INDEX; sent on every delivery, empty for R3 and tiles without ground), `lights` (PackedVector3Array relative to `origin`), `light_colors` (PackedColorArray; rgb = average colour, a = `clamp(sqrt(count) / 8, 0.125, 1)`). Lights are filled for R2 and R3 only.

Encodings:

- Building vertex COLOR: `r` = profile id / 8 (0 residential, 1 office, 2 retail, 3 industrial, 4 civic, 5 unknown), `g` = seed 0..1, `b` = floor height / 10 m, `a` = building height / 400 m. UV = meters (u along wall, v up).
- Ground COLOR: `r` = class / 16 (0 grass/park, 1 forest, 2 water, 3 residential, 4 commercial, 5 industrial, 6 other landuse, 8 road), `g` = lit road flag, `b` = road class / 8 (0 for areas), `a` = 1.

Guarantees: refining requests all 4 children as one sibling group; every requested tile is delivered; a parent is unloaded only after its 4 children were delivered and the swap fade finished; when coarsening, the parent is delivered again before its children are unloaded. Visibility rule (evaluated by the host): see `docs/contract.md` section 5 (until P2 it lived in `.claude/agents/godot-csharp-integrator.md`).

### Rings and data

- Quadtree cover: R0 z16 < 0.6 km, R1 z15 < 2.5 km, R2 z14 < 7 km, R3 z13 < 25 km. R0 full buildings and all roads, R1 boxes, R2 merged coarse blocks, R3 light points only.
- Sources: PMTiles v3 over HTTP range requests with a disk LRU cache (300 MB cap), or the synthetic city. Layers `buildings`, `landuse`, `roads` (see `data/README.md`).
- Environment variable `SIMPLANE_PROFILE=1` prints main-thread profiling lines (to be replaced by a `Diagnostics` setting in P1).

### Godot side (test bench `low-poly-map/`)

- `WorldStreamerFacade` (typed wrapper; probes optional methods `poll_fades`, `ground_height_at`, `debug_tiles`), `StreamerBridge`, `TilePool`, `TileCover`, `TileKey`, dithered LOD fades, ground and sprite shaders, `NightRenderController`, interim `TimeOfDay` and `DaylightMenu` (sun and night factor computed in C#).

### Not built

`api_version`, `configure_world` / world profile, `set_clock` / `daylight()`, `configure_imagery`, `attributions`, geodetic camera input, `origin_shifted` signal, window shader with light profiles, DEM terrain. See `docs/spec-library-packaging.md` (phases P1-P7) and `docs/spike-streamed-osm-city.md` (M6-M8).
