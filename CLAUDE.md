# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

"SimWorld" (working name; the repo folder is still `lowpolymap`, the Rust crates are `simworld-core` / `simworld-godot` / `simworld-cli`) is a streamed low-poly OSM city for the SimPlane flight game: a Rust GDExtension (`WorldStreamer`) streams PMTiles around a camera and generates everything; a Godot 4.7 (.NET/C#) addon (`addons/simworld/`) displays it. It started as a spike and is being turned into a reusable library with a test bench. The packaging plan is in `docs/spec-library-packaging.md` (phases P0-P7); this repo has finished P0 (baseline), P1 (core split: Cargo workspace, `World`, `Log`, `Diagnostics`), P2 (contract: `docs/contract.md`, `api_version`), P3 (config: world profile JSON + schema, `configure_world`, `world_profile()`, golden determinism hashes), P4 (host API: geodetic camera input and conversions, `origin_shifted` / `status_changed` signals, `status()`, `attributions()`, `shutdown()`, cache folder lock, several instances) and P5 (addon: `addons/simworld/` with `WorldView`, settings resource, global shader uniforms, `NightLook`, editor plugin, multi-platform `.gdextension`; the test bench consumes it; **not verified: the minimal iOS export**, see "Addon"). Contract version: `api_version` 1.11 (`docs/contract.md`; 1.0 = first breaking change, night windows W2 + W3; 1.1 = street lamps; 1.2 = aircraft warning beacons; 1.3 = R3 ground + `debug_stats()["latency"]`; 1.4 = procedural terrain phase 1, `layers` option; 1.5 = terrain mesh layer (`"t/"` keys), `set_terrain_detail`; 1.6 = `terrain_center` option, `status()["terrain_active"]`; 1.7 = world seed S1: `seed_world` option, `airports()`, `seed_world_info()`, `airport_lights`, ground class 7 + tint, terrain COLOR in a seed world, profile_version 6; 1.8 and 1.9 reserved; 1.10 = Tiles and LOD v2 T3: screen-space-error cover, `set_view`, `set_lod_quality`, profile `lod` section, `bands.r0..r2_edge_m` removed and `bands.r3_edge_m` renamed `bands.max_distance_m`, profile_version 7, `debug_stats` `tau_eff` / `lod_quality` / `lod_edges_m` / view keys; 1.11 = Tiles and LOD v2 T2b/T2c, Rust half: two-level archives (`simworld_levels`, R2 / R3 cut from the overview z11 tile), landmark layer `"l/z/x/y"` (opt-in `layers` value `"landmarks"`), synthetic city as a two-level source, `debug_stats` `data_levels` / `landmarks_*`; Godot half built, see "Addon"); crate version 0.5.0 (`CHANGELOG.md`).

## Commands

- Rust (from `rust/`, the workspace root, never from `low-poly-map/`): `cargo check`, `cargo test`, `cargo build` (debug `target/debug/libsimworld_godot.dylib` that the editor loads), `cargo build --release`. `cargo tree -p simworld-core | grep -i godot` must print nothing.
- **Addon sync (after every edit under `addons/simworld/`, before `dotnet build` or running the bench):** `tools/sync_addon.sh` copies `addons/simworld/` to `low-poly-map/addons/simworld/` (generated, git-ignored; the addon source is at the repo root, never edit the copy). It first pulls Godot-generated `.uid` files that exist only in the copy back to the source (commit them), and leaves out `simworld.gdextension` and `bin/` (the bench loads the library from `rust/target` through `low-poly-map/simplane_world.gdextension`, the editor-only dev override).
- C# (from `low-poly-map/`): `dotnet build`.
- Addon libraries: `tools/build_addon.sh [--release] [--ios]` builds `simworld-godot` for this OS and copies it to `addons/simworld/bin/<os>/` (git-ignored; macOS universal via `lipo` when both rust targets are installed, else the host architecture only). Needed only for a project that uses the addon's own `.gdextension` (a game, the fresh-project check), not for the bench.
- Godot binary is not on PATH: `G=~/Downloads/Godot_mono.app/Contents/MacOS/Godot`. Headless smoke test, from `low-poly-map/`: `$G --headless --path . --quit-after 120`. It prints the godot-rust init line, the Godot version, the `[WorldView]` lines (tile source, `poll_fades available`, `WorldStreamer configured ... [simworld-godot <version> (build ...)]`, disk cache stats, first tile, a `[WorldView] debug_stats {...}` line) and some `slow upload` lines. A green run has no errors and a `first tile` line. Add `-- --tile-url=` for the offline synthetic city.
- Run the test bench: `$G --path .` (add user arguments after `--`, see `low-poly-map/CLAUDE.md`).
- Performance diagnostics (same approach as the SimPlane game: frame percentiles, CPU / GPU / memory / draw calls, markers, `--benchmark=<name> [--soak=S]` with scripted paths, JSON result, per-machine baselines, F4 overlay): `low-poly-map/scripts/Diagnostics/`, see "Diagnostics" in `low-poly-map/CLAUDE.md`. The addon only exposes `WorldView.Timings` / `LastUploads` / `EndTimingFrame()`.
- Hot reload: keep the editor open, `cargo build`, refocus the editor window (`reloadable = true` in `simplane_world.gdextension`). `WorldStreamer` is not a tool class, so it only runs in-game, not in the editor.
- Tile build: `data/build_tiles.sh` (Docker, planetiler 0.10.2) writes `data/out/vilnius.pmtiles`; `data/serve.sh` serves it with Range support at `http://127.0.0.1:8787/`. See `data/README.md`.
- Two-level bake (Tiles and LOD v2, T1b; from `rust/`): `cargo run --release -p simworld-cli -- bake ../data/out/vilnius.pmtiles ../data/out/vilnius-v2.pmtiles` (detail z14 + overview z11 with blocks / lights / landmarks, prints sizes, verifies); `bake --verify <file> [--input <src>]` checks an archive. See `data/README.md`.

## Addon (`addons/simworld/`, P5)

- `runtime/` (namespace `SimWorld`, compiled into the host's assembly; `WorldView`, `TilePool` and the facade are partial classes split by concern: `WorldView.Frame/Upload/Fades/Unload/Time/CullMargins/Debug/Timings/Taps/View.cs`, `TilePool.Fades/Sprites/Warmup.cs`, `WorldStreamerFacade.Ready/Lod.cs`): `WorldView` (the entry node: owns the streamer, runs the per-frame calls, uploads, fades, shifts the origin; no default origin, no command line; `AutoStart` or `Start()`, `SetTime(hour, night)`, C# event `OriginShifted`), `IWorldCameraSource` (+ `Camera3DSource` adapter; a `Camera3D` needs no code), `WorldRenderSettings` (resource: upload budget, prewarm, debug, building/ground/light-sprite material tunables), `NightLook` (resource: glow threshold/intensity and fog on an `Environment` the host passes in; exposure, tone map, sun, sky stay in the host), `ShaderGlobals` / `AddonPaths`, `SimWorldPlugin` (editor plugin), `WorldStreamerFacade`, `TilePool`, `TileCover`, `TileKey`.
- Terrain (api 1.5, host side built): `WorldView.EnableTerrain` (opt-in, sends `layers: ["world","terrain"]`) plus `terrain_center` = the startup origin (api 1.6, so a reconfigure that moves the origin keeps the relief) and reads `status().TerrainActive` and `TerrainEnabled` (profile override `terrain.enabled`), `TerrainCover` + `TerrainPool` / `TerrainNodes`, `shaders/terrain.gdshader`, `WorldRenderSettings.Terrain*`, `SetTerrainDetail`, `TileKey.TryParse(key, out packed, out isTerrain)`; the camera far plane (reach x 1.15) and the day fog are host policy (`NightLook.TerrainDayFog*`). Default off = the flat world exactly.
- Frame cost (host performance pass; no contract change): releasing a tile (`TilePool.Release` / `TerrainPool.Release`) hides the set at once and queues it (`RetireQueue`), `DrainRetired` clears its meshes and sprite sets within `WorldRenderSettings.ReleaseBudgetUs` (1 ms, at least one set per frame per pool), `Acquire` clears a retired set on demand and never hands one out before it was cleared; `FreeCount` = free + retiring. The five light sprite sets sit under one `TileNodes.Sprites` container that `WorldView.SetTime` hides while the night factor is below 0.02 (shown again above 0.05; `TilePool.SetSpritesVisible`, one call per held tile on a change, new sets follow the pool's state): by day they drew only additive black. Beacons go with them (their shader is also zero by day); a daylight strobe would need a day term in `beacon_light.gdshader` and its own container. Sprite uploads stage through shared per-size float arrays (`TilePool.Sprites.cs`, no per-set buffers; instance counts only grow, shrink at more than twice the need). `MaterialPrewarm` draws the 16 world materials, the dither variants included, tiny in front of the camera for 24 frames at start (`PrewarmMaterials`; skipped headless) so the shader / pipeline compile does not hit the first fade. Frustum-cull margins are per tile (`CullMargins`, `WorldView.CullMargins.cs`): the earth-curvature drop at the tile's far edge plus 600 m of slack, floor 0.5 m, written at upload and re-checked 4 times a second (`WorldView.CullMarginWrites`); `TilePool.CurveCullMargin` stays only for the runway markings. `poll_fades` is read without allocating while its key set is unchanged (`FadeKey` cache in `WorldView.Fades.cs`; the dictionary is enumerated and the key strings parsed only when a fade starts or ends). Debug checks (`WorldRenderSettings.DebugChecks`, default off; the bench turns them on for headless runs, `*-selftest`, `--geodetic-test`, `--hole-check` and `--debug-checks`, never for `--benchmark` / `--soak`): the periodic `VerifyCover` and the first-tile `debug_stats` print. Delivered tiles the host cannot draw (an entry without a key, a mesh array that is not an Array or has no vertex slot, a mesh Godot rejects, a short light colour array, a non-Array `poll_ready`) are logged once per key and counted (`WorldView.UploadProblems`, F1 overlay "UPLOAD PROBLEMS"). `AsMeshArrays` no longer copies the vertex array to read its length (the arrays go straight into `AddSurfaceFromArrays`).
- Screen-space LOD (api 1.10, host side built, gated: a library below 1.10 gets nothing and logs one `set_view unavailable` line): `WorldView.UpdateView` sends `set_view(fov_y_deg, viewport_h_px, forward)` before `update_camera` on change (fov > 0.05 deg, height, direction > 2 deg) and after every configure, `WorldRenderSettings.LodPixelScale`, `SetViewOverride` (bench `--view=` / `--cam-fov=`), facade `HasSetView` / `SetView` / `SetViewCalls`, `StreamerStats.TauEff` / `LodQuality` / `LodEdgesM` / `ViewFovYDeg` / `ViewHeightPx` / `DataTiles*` / `RequestsSkipped*`. S2 + S3 host half: `LatestKnownMinor` = 10, facade `SetLodQuality` (gated 1.10), `WorldView.SetLodQuality` / `ReadLod` / `LodEdgesM` / `TauEff` / `LodQuality` (the band edges are no longer fixed: `BandsText` shows the live `lod_edges_m`; `bands.rN_edge_m` in `profile_overrides` is a profile error), `WorldRenderSettings.BlendFollowsLod` (the window / sprite blend, the street pool fade and the sprites' far fade follow `lod_edges_m`, see low-poly-map/CLAUDE.md), the runway marking ring edges follow the live edges, settings panel = live Detail slider + Max distance, bench `--area` = `set_lod_quality(1/area)` + `bands.max_distance_m`, headless / self-test runs pin the view to 60 deg / 1080 px, `--lod-selftest`.
- Landmark layer (api 1.11, host side built, gated: a library below 1.11 is never sent `"landmarks"`; contract 9b): `WorldView.LandmarksEnabled` (default true; bench `--no-landmarks`) adds `"landmarks"` to `layers` on every configure and reconfigure (with `"terrain"` when that runs), `LandmarksActive`, `TileKey.TryParse(key, out packed, out TileLayer layer)` (`TileLayer` = World / Terrain / Landmarks; the 2-argument overload still means a plain vector key), `LandmarkCover` (`WorldView.LandmarkCover`: a flat `Dictionary` of `l/z/x/y` tiles, visible from upload to unload, no quadtree rule, no dither, shifted with the origin, cleared by the reconfigure's unload batch plus a stray sweep) over nodes from the SAME vector `TilePool` (building material with the windows, light sprites that cross-fade with the windows like R1, beacons; no ground / street / airport sets), `ReadyTile.IsLandmark`, `DebugTile.Layer` / `TileState.Empty`, `StreamerStats` `HasDataLevels` / `DetailZoom` / `OverviewZoom` / `TwoLevel` / `LandmarksInArchive` / `LandmarksLoaded` / `Pending` / `Empty`, counters `LandmarkReadyTotal` / `LandmarkKeysSeen` / `LandmarkFadeKeysSeen` (must stay 0). `LatestKnownMinor` = 11. The pool in use equals vector + landmark tiles. Terrain: `set_terrain_detail` is a tau scale since api 1.10 (`WorldView.TerrainTauPx` / `TerrainTauEff`), the settings slider is the raw scale labelled coarseness.
- Render height, pool trim, memory budget (host only, no contract change): `set_view` carries the **3D render height** = the camera viewport's height x its `Scaling3DScale` (project setting `rendering/scaling_3d/scale`) x `WorldRenderSettings.LodPixelScale` (an extra bias, default 1); `CameraViewReader` measures it every frame, so a window resize or a scale change re-sends `set_view` (the light sprite pixel scale uses the render height too); `WorldView.ViewHeightPx` / `ViewportHeightPx` / `RenderScale`, one `[WorldView] set_view ... render height` log line per change, F1 `view:` line and `LatencyLog` show it; a `SetViewOverride` height is used as is. `PoolTrimmer` gives idle pool memory back: `TilePool` (vector + landmark nodes) and `TerrainPool` destroy free node sets (`Trim(delta)` once per frame from `WorldView`, a few per frame within 0.5 ms) when the free list stayed above `max(PoolTrimMinFree 64, PoolTrimPeakShare 0.25 x recent peak in use)` for a whole `PoolTrimHoldS` (30 s, tumbling window, 0 = never shrink) window; `TotalCreated` / `PoolCreated` is the number of sets that EXIST now (so tile roots == created still holds), `Trimmed` the destroyed ones; `[PoolTrim]` log lines. `WorldRenderSettings.MemoryBudgetMb` (`MemoryBudget.Apply`): passed as profile override `memory.budget_mb` on every configure unless the host's overrides or profile file carry the key and the library has api 1.10; 0 = library default (512), the property default is 224 on mobile (`OS.HasFeature` mobile / ios / android) and 0 on desktop. Bench: `--render-scale=`, `--memory-budget-mb=`, `--pool-trim-hold=`.
- World seed S1 (api 1.7, host side built; `docs/spec-world-seed.md` 11d): `WorldView.SeedWorld` (path of a `world.json`; non-empty = seed world: `TileUrl` ignored with a warning, terrain layer forced on, profile overrides `terrain.enabled` true and `flat_radius_m` / `flat_blend_m` 0 added unless the host set them, `cache_dir` empty, `seed_world` passed on every configure and reconfigure), `SeedWorldActive`, `SeedInfo` (`seed_world_info()` as a typed `SeedWorldInfo` record, logged at start), `Airports` (`airports()` as `AirportInfo` / `RunwayInfo` / `RunwayEnd` records, re-read on configure and on every origin shift), facade wrappers `Airports()` / `SeedInfo()`, `ReadyTile.AirportLights`, `DebugTile.Source`. Shaders: `ground.gdshader` class 7 aeroway by sub-kind (COLOR b) and the countryside tint (COLOR g on class 0 / 1 areas; roads are told apart by r == 8/16 first), `terrain.gdshader` class colours from the seed terrain COLOR (r = class / 8 as one-hot weights; r * 8 == 8, i.e. a missing COLOR, keeps the altitude palette), both through `seed_palette.gdshaderinc` (`WorldRenderSettings.Seed*`). Airport lights (`airport_lights` / `airport_light_colors`): a fourth sprite set per tile (`TileNodes.AirportLights`, own material `TilePool.AirportLightMaterial`, `WorldRenderSettings.AirportLight*`: fixed colours, no window cross-fade, no grazing / altitude thinning, brightness scaled by alpha / 0.35, alpha 0.125 in the buffer so the sprite shader does not read them as clusters). Runway markings: `AirportMarkings` (edge lines, dashed centreline, threshold bars, aiming-point bars from the `airports()` runway ends, one mesh for the airports within 4.5 km of the camera, rebuilt on origin shifts) with `airport_marking.gdshader`; the drawn runway sits above `ground_height_at` by stacking level 3 x `ground.rN.lift_step_m` per ring (0.06 / 0.18 / 0.45 / 1.5 m; no drape lift inside an airport fence, generator 2, contract section 9 "Airports"): `WorldView.ComputeRunwayLifts` uses that rule when `seed_world_info()["generator_version"]` >= 2 (`WorldRenderSettings.MarkingRunwayLevel` = 3; `WorldView.RunwayLift` / `RunwayLiftRule` expose the result) and, for a generator-1 or older library, still replays the old drape rule (terrain bands x `detail_scale_max` + level 10 x step: 1.2 / 3.6 / 9.5 / 25 m). Bench: `--world=`, `--seed-spot=`, `--seed-selftest`, `SeedTwoCities.tscn`, F1 seed line.
- Dither fades (`FadeMaterials`): a fading tile rents one clone of the dither variant per drawn node (building, ground, five sprite sets; terrain 1) and writes `fade` / `fade_parity` / `fade_mul` as plain uniforms. **Never use `instance uniform` in an addon shader:** Godot gives every node that is assigned a material declaring one 16 entries of a 4096-node buffer for good and reads them as 0 once it is full (invisible tiles, black sprites; see CHANGELOG). Parameters of the world materials go through `TilePool` / `TerrainPool` setters, which write the template and every clone. `--fade-selftest` guards it.

- `TerrainCollision` (optional, `WorldView.TerrainCollisionEnabled`, default off): one `StaticBody3D` + `HeightMapShape3D` patch (33 x 33 samples, 40 m apart) centred under the camera, filled from `ground_height_at` and re-centred/shifted with the camera and origin; the exact heightfield, not the drawn terrain triangles (differ by up to the band `max_error_m x detail`); no collision for buildings or far terrain.

## Architecture

- **Rust owns the world, Godot only displays it.** The `WorldStreamer` Node does the quadtree cover by 3D slant distance (R0 z16 < 0.6 km, R1 z15 < 2.5 km, R2 z14 < 7 km, R3 z13 < 25 km), PMTiles fetching over HTTPS range requests, disk LRU cache, MVT decoding, meshing, ground meshes and light points on worker threads (tokio for I/O, rayon for meshing, crossbeam channel back). C# drives the camera, uploads finished tiles (at most 2 per frame, at most 2 ms) and renders.
- **The `WorldStreamer` API is a contract** shared by both sides: `api_version`, `configure`, `configure_world`, `world_profile`, `update_camera`, `update_camera_geodetic`, `geodetic_to_local`, `local_to_geodetic`, `poll_ready`, `poll_unload`, `poll_fades`, `take_origin_shift`, `attributions`, `status`, `shutdown`, `debug_stats`, `debug_tiles`, `ground_height_at`, signals `origin_shifted` and `status_changed`, plus the ready-tile dictionary shape (incl. the quadtree sibling-swap visibility rule and dithered fades) and the vertex COLOR encodings. **The contract is `docs/contract.md`** (single source; the agent files only point to it). Any change updates that file, `api_version` (`API_MAJOR`/`API_MINOR` in `rust/simworld-core/src/lib.rs`) and `CHANGELOG.md` in the same commit. `api_version` = contract `major.minor`, independent of the crate version: a minor bump is additive only, a major bump is breaking. `cargo test` fails if the constants and the `api_version:` line of `docs/contract.md` disagree or a `#[func]` or `#[signal]` is missing from it.
- **Floating origin:** f64 ENU inside Rust, f32 relative to origin in Godot; re-center beyond 5 km and shift camera + all tile roots in the same frame.
- **Coordinates:** Y-up, x = east, z = -north, meters.
- **Determinism:** same tile gives the same mesh and the same lit windows (seeded by OSM id). Pinned by `simworld-core` `golden_tests` (quantized per-tile hashes of the synthetic city, all bands; regenerate only for an intended change with `SIMWORLD_UPDATE_GOLDEN=1 cargo test -p simworld-core golden -- --nocapture`).
- **Tuning is data:** band edges, DP tolerances, budgets, light profiles, road/area tables etc. live in the world profile (`docs/contract.md` 3.2), not in module constants. A changed default changes host-visible behaviour: update `default.json`, the schema (the tests enforce both) and `CHANGELOG.md`. Structural values (4 bands, zooms 13-16, layer names) stay constants.

## Constraints

- Renderer is **Mobile** (`low-poly-map/project.godot`); don't use Forward+-only features. Physics is Jolt. Windows uses D3D12.
- Desktop first, but stay iOS-ready: Rust uses rustls (no OpenSSL), no desktop-only crates, crate-type `cdylib` + `staticlib` for a later `.xcframework`.
- Never call Godot APIs from Rust worker threads; convert to Packed arrays only on the main thread.
- Pool `MeshInstance3D`/`MultiMeshInstance3D` nodes instead of freeing/allocating per tile.
- Tile data comes from a self-hosted custom `.pmtiles` (planetiler profile with a `buildings` layer keeping building `kind`), never public OSM tile servers. Attribution "© OpenStreetMap contributors" is required.
- No git commits, tags or pushes unless the user asks. `.godot/`, `rust/target/`, `data/out/`, `data/sources/` are generated and ignored (`.gitignore`).

## Subagents
